## 2. 스케일링 곡선

같은 세션 교차 측정 3라운드 중앙값. N=4 만 불균등 분할(`9,9,7,7`).

| 노드 | prefill | 배수 | 효율 | 모델 예측 | 실측/예측 = η_balance |
|---|---|---|---|---|---|
| 1 | 30,110 | 1.00× | — | — | 100 % |
| 2 | 18,259 | 1.65× | 83 % | 1.93× | 85 % |
| 4 | 11,516 | 2.61× | 65 % | 3.61× | 72 % |
| 8 | 7,973 | 3.78× | 47 % | 6.40× | 59 % |

> 세션 간 편차가 10 % 있다. 다른 세션에서 PP8 이 7,165 ms(4.39×)로 측정됐다.
> **배수 비교는 반드시 같은 세션 안에서** 해야 한다.

노드를 늘릴수록 **단조적으로 빨라진다.** 다만 효율은 47 % 까지 떨어진다.

## 3. 예측 모델

```
속도향상(N) = M·N / (M + N − 1),   M = S / B_min
```

`M` 은 마이크로배치 수, `B_min` 은 GEMM 타일 효율이 유지되는 최소 청크 폭
(Pi5 실측 **16**). 버블만 고려한 상한이다.

**따라오는 결과 두 가지:**

- `N → ∞` 에서 속도향상 상한은 `M = S/B_min` 이다. S=448 이면 28배.
  **프롬프트 길이가 유효 노드 수의 상한을 정한다.**
- 실측/예측 비 `η_balance` 가 SBC 고유 손실이며, N 과 함께 100 → 59 % 로 떨어진다.

## 4. η_balance 의 정체 (분해 완료)

| 원인 | 성질 | 대응 | 신규성 |
|---|---|---|---|
| 하드웨어 개체차 (`.166` 이 40 % 느림) | 정적 | 측정 기반 불균등 분할 | 없음 (PipeEdge) |
| 마지막 스테이지 상수 (final norm + lm_head, 35 ms) | 정적·구조적 | 분할 시 상수 보정 | 없음 |
| **레이어 입자도** | **구조적 한계** | **서브레이어 분할 (미구현)** | **여기** |

**입자도가 핵심 제약이다.**

| | 스테이지당 레이어 | 레이어 1개 / 목표 스테이지 시간 | 균형화 |
|---|---|---|---|
| N=4 | 8 | 11 % | 성공 (2.52 → 2.81×) |
| N=8 | 4 | 22 % | **실패** (7,165 → 7,360) |
| N=16 | 2 | ~44 % | 사실상 불가 |

N=8 에서는 느린 노드를 3레이어로 줄이면 다른 노드가 5레이어가 되어 **새 최대**가
된다. 이론 이득 12 % 가 세션 편차 10 % 에 묻힌다.

## 6. 부수 관찰

- **8 GB 노드가 16 GB 노드보다 빠르다** (120~124 vs 132~170 ms).
  메모리 용량은 속도와 무관하다. 이종 클러스터에서 "메모리 큰 노드 = 좋은 노드"가 아니다.
- **최적 청크 폭은 16~32** 이고 이는 GEMM 타일 구조에서 온다. 8 이면 2배 손해,
  448 이면 attention 이 커진다. 이 구간이 `M` 을 통해 스케일링 상한을 정한다.
- **분산 통신은 병목이 아니었다.** 실제 전송 시간은 언제나 1초 미만이었고,
  `syncWait` 이 80 % 였던 것은 전부 다른 노드가 무언가에 막혀 있었기 때문이다.

## 7. 시도했으나 채택하지 않은 것

| 방향 | 결과 |
|---|---|
| Ring CP (토큰 축 분산) | 보류 — 통신량이 PP 의 8배(168 vs 21 MB) |
| TP (텐서 병렬) | 보류 — 통신이 매 레이어 임계경로, N 이 커져도 안 줄어듦. 게다가 코드가 깨져 있었음 |
| SP (시퀀스 병렬) | 사용 불가 — 단일 요청용 축이 아님 (P/D 분리용) |
| 임베딩 양자화 | 불필요 — 워커는 임베딩이 없어 8 GB 로 충분 |
| 토큰 가지치기 | 실패 — 1.08배 얻으려고 품질 42 % 손실 |
