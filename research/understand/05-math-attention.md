# 0부. 준비

## 0-1. 벡터, 내적, 노름

**벡터**는 숫자를 순서대로 나열한 것이다. `x = (x_1, …, x_d)`.
이 문서에서 `d` 는 항상 차원 수다.

**내적(inner product)**:

```
a · b = Σ_{c=1}^{d} a_c b_c        (스칼라 하나가 나온다)
```

**노름(길이)**:

```
‖a‖ = √(a · a) = √(Σ a_c²)
```

**핵심 성질** — 내적은 각도를 잰다:

```
a · b = ‖a‖ ‖b‖ cos θ
```

`θ` 는 두 벡터 사이의 각도다. 따라서:

| 상황 | `a·b` |
|---|---|
| 방향이 같다 (θ=0) | `+‖a‖‖b‖` — 최대 |
| 직교 (θ=90°) | `0` |
| 반대 (θ=180°) | `−‖a‖‖b‖` — 최소 |

> **내적이 "유사도"인 이유가 이것이다.** 방향이 비슷하면 크고, 무관하면 0이다.

다만 **크기에도 비례**한다는 점에 주의한다. 이것이 나중에 `√d` 문제를 만든다.

## 0-2. 행렬 곱은 무엇을 하는가

`W` 가 `m × d` 행렬이고 `x` 가 길이 `d` 벡터일 때:

```
(Wx)_i = Σ_{c=1}^{d} W_{ic} x_c        ← W 의 i번째 행과 x 의 내적
```

즉 **`Wx` 의 각 성분은 "x 를 어떤 방향으로 재어 본 값"** 이다.
`W` 의 행 하나하나가 하나의 "질문"이고, 결과가 그 답이다.

`W_q x` 를 "x 에서 질문 벡터를 뽑아낸다"고 읽는 근거가 여기 있다.
행렬 곱은 **선형 사상**이며, 그 성질은 [04-concepts §7-1](04-concepts.md#7-1-선형-사상) 에 있다.

**전치(transpose)** `Wᵀ` 는 행과 열을 바꾼 것이다. 유일하게 필요한 성질:

```
(Wa) · b = a · (Wᵀb)          ← 한쪽의 행렬을 반대쪽으로 넘길 수 있다
(AB)ᵀ = BᵀAᵀ
```

이 한 줄이 1부의 핵심 변형을 만든다.

## 0-3. softmax

**하는 일**: 임의의 실수 벡터를 **확률분포**로 바꾼다.

```
softmax(s)_j = e^{s_j} / Σ_k e^{s_k}
```

**성질 세 개:**

```
① 모든 성분이 양수        (e^x > 0)
② 다 더하면 1            (분모가 곧 합)
③ 순서를 보존한다         (e^x 가 증가함수)
```

**왜 하필 지수함수인가.** 세 가지 이유가 있고, 세 번째가 이 프로젝트에서 실제로 쓰인다.

1. 음수 점수도 양수 확률로 보낸다.
2. 차이를 증폭한다 — `s` 차이가 크면 확률 차이가 극단적이 된다("경쟁").
3. **기준점 이동이 곱셈 하나다.**

```
e^{s_j − m} = e^{s_j} · e^{−m}
```

모든 항에 같은 상수가 곱해지므로 **분자·분모에서 약분된다.**

```
softmax(s − m·1) = softmax(s)        임의의 상수 m 에 대해
```

> **이 불변성이 online softmax([4-1](#4-1-online-softmax-가-정확한-이유))와
> LSE merge([4-2](#4-2-lse-merge-의-정확성-증명))의 전부다.**
> 오버플로를 막으려고 최대값을 빼도 결과가 안 변하는 이유이기도 하다.

## 0-4. 기댓값과 분산

`√d` 유도에만 쓴다.

```
E[X]   = X 의 평균
Var[X] = E[(X − E[X])²]        평균에서 얼마나 흩어져 있는가
std[X] = √Var[X]
```

**필요한 규칙 두 개:**

```
X, Y 가 독립이면   E[XY] = E[X]E[Y]
X, Y 가 독립이면   Var[X + Y] = Var[X] + Var[Y]      ← 분산은 더해진다
```

두 번째가 핵심이다. **표준편차가 아니라 분산이 더해지므로**, `d` 개를 더하면
표준편차는 `√d` 배가 된다. 여기서 `√d` 가 나온다.

# 1부. Attention

## 1-1. 출발점: 연상 메모리

토큰 `i` 가 필요한 것은 이것이다.

> 앞쪽 토큰 중 **내가 지금 찾는 것과 관련 있는** 토큰의 내용을 가져와라.

일반 딕셔너리는 키가 정확히 일치해야 한다. 언어에서는 그럴 수 없으므로
**"비슷한 만큼 섞어서" 가져오는 soft lookup** 이 된다.

```
하드 : out = table[key]                     정확히 하나
소프트: out = Σ_j sim(q_i, k_j) · v_j        전부에서 조금씩
```

이 한 줄에서 세 역할이 갈라진다.

| | 정의 | 역할 |
|---|---|---|
| `q_i = W_q φ(x_i)` | query | 내가 **찾는** 것 |
| `k_j = W_k φ(x_j)` | key | 내가 **찾아질** 때의 간판 |
| `v_j = W_v φ(x_j)` | value | 찾아지면 **주는** 내용 |

`φ` 는 RMSNorm 이다([04-concepts §1-6](04-concepts.md#1-6-정규화-layernorm-과-rmsnorm)).
실제 입력은 `x` 가 아니라 `φ(x)` 이므로 이 문서는 그렇게 쓴다.

완성된 식:

```
s_ij  = (q_i · k_j) / √d        + mask
a_ij  = softmax_j(s_ij)
out_i = Σ_j a_ij v_j
```

## 1-2. 왜 Q 와 K 를 따로 만드나

**후보 1: 유사도를 `x_i · x_j` 로 직접 재면 안 되나?**

내적은 **대칭**이다.

```
x_i · x_j = x_j · x_i
```

그런데 언어의 참조 관계는 대칭이 아니다.

```
"그것" ──찾는다──> "고양이"      ✔ 필요
"고양이" ──찾는다──> "그것"       ✘ 이유 없음
```

대칭 유사도로는 **한 방향만 강한 관계를 표현할 수 없다.** 게다가

```
x_i · x_i = ‖x_i‖² ≥ |x_i · x_j|      (코시-슈바르츠)
```

이므로 **모든 토큰이 자기 자신에 최대 점수**를 주게 된다. 정보를 못 가져온다.

**후보 2: 행렬 하나만 쓰면? `(Wx_i)·(Wx_j)`**

여전히 대칭이다. `x_iᵀWᵀW x_j` 이고 `WᵀW` 는 대칭행렬이다.

**해답: 서로 다른 두 행렬.** 0-2 의 전치 규칙을 쓰면:

```
s_ij = (W_q φ(x_i)) · (W_k φ(x_j))
     = φ(x_i)ᵀ W_qᵀ W_k φ(x_j)
     = φ(x_i)ᵀ M φ(x_j)          ,    M ≜ W_qᵀ W_k  ∈ R^{h×h}
```

이 형태를 **이중선형 형식(bilinear form)** 이라 한다. 여기서 두 결론이 나온다.

**① 학습되는 실체는 `M` 하나다.** Q/K 분리는 `M` 을 만드는 방법일 뿐이다.
`M ≠ Mᵀ` 이 허용되므로 방향성 있는 관계를 표현한다.

**② `M` 은 구조적으로 저랭크다.** 헤드 하나에서 `W_q, W_k` 는 `d × h = 128 × 4096` 이므로

```
rank(M) ≤ min(rank W_q, rank W_k) ≤ 128        (h = 4096 인데)
```

이건 결함이 아니라 설계다.

| | 파라미터 (헤드 1개) |
|---|---|
| `M` 을 통째로 두면 | 4096 × 4096 = 16.8 M |
| `W_q, W_k` 로 분해 | 2 × 128 × 4096 = 1.05 M |

**16배 절약 + 정칙화.** [04-concepts §7-6 저랭크 근사](04-concepts.md#7-6-저랭크-근사)
가 다루는 바로 그 구조가 attention 안에 처음부터 들어 있다.

> `d_head` 는 "헤드를 나눈 결과"이기도 하지만, 동시에 **점수 함수의 랭크 상한**이다.

## 1-3. 왜 V 를 또 따로 만드나

`out_i = Σ_j a_ij φ(x_j)` 처럼 원본을 그대로 가져오면 안 되나?

**"어떻게 찾아질 것인가"와 "찾아지면 무엇을 줄 것인가"는 다른 정보**이기 때문이다.

```
"고양이" 라는 토큰
  K 로서 : 명사다 / 동물이다 / 단수다        ← 검색되기 위한 특징
  V 로서 : 고양이라는 개체의 의미 표상        ← 실제로 전달할 내용
```

하나의 벡터가 둘을 겸하면 한쪽을 최적화할 때 다른 쪽이 망가진다.
분리하면 `W_k` 와 `W_v` 가 독립적으로 학습된다.

**부수 효과**: `V` 의 출력 차원이 자유로워진다. 실제로 attention 출력은
`W_o` 를 거쳐 residual stream 으로 돌아가므로, `V` 는 `d_head` 차원이면 된다.

**볼록 결합이라는 성질도 중요하다.**

```
a_ij ≥ 0,  Σ_j a_ij = 1    ⟹    out_i ∈ conv{v_0, …, v_i}
```

출력이 `v` 들의 볼록껍질 안에 갇히므로 **크기가 폭발하지 않는다.**
residual stream 에 더해지는 값이 안정적으로 유지되는 구조적 이유다.

## 1-4. `√d` 는 어디서 나왔나

학습 초기에 `q_c, k_c` 가 서로 독립이고 `E=0, Var=1` 이라고 하자. 그러면

```
s = q · k = Σ_{c=1}^{d} q_c k_c

E[s]   = Σ_c E[q_c]E[k_c] = 0
Var[s] = Σ_c Var[q_c k_c]                    (독립이므로 분산이 더해진다)
       = Σ_c ( E[q_c²k_c²] − E[q_c k_c]² )
       = Σ_c ( 1·1 − 0 ) = d

std[s] = √d
```

`d = 128` 이면 **std ≈ 11.3** — 점수가 대략 ±34 (3σ) 범위에 퍼진다.

**여기에 softmax 를 걸면 무슨 일이 생기나.**

```
가장 큰 점수와 두 번째의 차이가 예컨대 10 이면
        e^{10} ≈ 22,026 배
```

사실상 one-hot 이 된다(**saturation**). 그러면

```
∂ softmax(s)_j / ∂ s_k ≈ 0        (거의 상수 함수)
```

이라 **gradient 가 흐르지 않아 학습이 죽는다.**

**교정**: 분산을 1로 되돌린다.

```
s' = s / √d    ⟹   Var[s'] = d / (√d)² = 1
```

| 나누는 값 | Var | 결과 |
|---|---|---|
| 없음 | `d` = 128 | 포화. 학습 불가 |
| **`√d`** | **1** | **적당한 경쟁** |
| `d` | `1/d` | 지나치게 평평 — 거의 균등 평균 |

> **`√d` 는 임의의 상수가 아니라 "softmax 입력의 표준편차를 1로 맞추는 값"이다.**
> 학습 후에도 대략 유지되도록 정규화(`φ`)가 스케일을 잡아 준다.

## 1-5. 멀티헤드와 GQA 의 수식적 의미

**멀티헤드**: `h = 4096` 을 `n_h = 32` 개 헤드 × `d = 128` 로 쪼개 각각 독립으로 위 계산을 한다.

```
out_i = W_o · concat( head_1(i), …, head_32(i) )
```

의미: **하나의 저랭크 `M` 대신, 서로 다른 32개의 랭크-128 `M_r` 을 합친다.**

```
전체 점수 구조 = { M_1, …, M_32 },   각 rank ≤ 128
```

랭크 하나로 4096차원 관계를 표현할 수 없으니, **여러 개의 저랭크 뷰**로 나눈 것이다.
헤드끼리 완전히 독립이므로 **헤드 축은 병렬화가 자유롭다** — TP 가 이 축을 쓴다.

**GQA**: 쿼리 헤드는 32개 그대로 두고, K/V 헤드만 `n_kv = 8` 로 줄여 4개씩 공유한다.

```
head_r 의 점수 :  q_r · k_{g(r)}      ,  g(r) = ⌊r / 4⌋
```

수식적으로는 **`M_r = W_{q,r}ᵀ W_{k,g(r)}` 에서 오른쪽 인자를 4개 헤드가 공유**하는 것이다.
`M_r` 들이 완전히 독립이 아니라 "같은 K 부분공간 위에서 서로 다른 질문을 던지는" 구조가 된다.

```
kvDim = n_kv × d = 8 × 128 = 1024        (h = 4096 의 1/4)
```

**이 `kvDim` 이 3부의 모든 크기 계산에 등장한다.**

| | `n_kv` | `kvDim` | KV 캐시 |
|---|---|---|---|
| MHA | 32 | 4096 | ×4 |
| **GQA** | **8** | **1024** | **×1 (기준)** |
| MQA | 1 | 128 | ÷8 |

# 2부. RoPE

## 2-1. Attention 은 집합 함수다 (증명)

**주장**: mask 가 없으면, 토큰 순서를 바꿔도 attention 의 값은 변하지 않는다.

순열 행렬 `P` (각 행·열에 1이 하나씩, `PᵀP = I`)로 입력을 섞는다.

```
X' = PX

Q' = X'W_q = PXW_q = PQ            (K', V' 도 동일)

S' = Q'K'ᵀ/√d = (PQ)(PK)ᵀ/√d = P (QKᵀ/√d) Pᵀ = P S Pᵀ
```

softmax 는 **행별 연산**이고 `PSPᵀ` 는 `S` 의 행과 열을 같은 방식으로 재배열한 것이므로:

```
A' = softmax_row(P S Pᵀ) = P · softmax_row(S) · Pᵀ = P A Pᵀ

O' = A'V' = (P A Pᵀ)(P V) = P A (PᵀP) V = P A V = P O        ∎
```

> **`Attn(PX) = P · Attn(X)`**
> 순서를 바꾸면 **출력의 순서만** 바뀌고 값은 그대로다.

FFN 과 RMSNorm 은 토큰별 독립이므로 같은 성질을 갖는다. 따라서

> **위치 인코딩이 없으면 트랜스포머 전체가 집합 함수다.**
> "개가 사람을 물었다"와 "사람이 개를 물었다"가 구분되지 않는다.

**단서 하나**: causal mask 가 있으면 `P S Pᵀ` 형태가 깨진다. 토큰 `i` 는 정확히
`i+1` 개를 볼 수 있으므로 절대 위치가 간접적으로 새어 나온다(NoPE 계열 연구가
관측한 현상). 하지만 "몇 칸 앞"이라는 **상대 거리는 여전히 표현되지 않으므로**
명시적 위치 인코딩이 필요하다.

## 2-2. 더하기 방식이 왜 부족한가

고전 방식(sinusoidal / learned absolute)은 위치 벡터를 **더한다**: `x_t ← x_t + p_t`.

점수를 전개해 보면 문제가 드러난다.

```
q_i·k_j = ⟨W_q(x_i+p_i), W_k(x_j+p_j)⟩

        = ⟨W_q x_i, W_k x_j⟩     내용 × 내용   ← 원하는 항
        + ⟨W_q x_i, W_k p_j⟩     내용 × 위치
        + ⟨W_q p_i, W_k x_j⟩     위치 × 내용
        + ⟨W_q p_i, W_k p_j⟩     위치 × 위치   ← 위치 관계는 여기에만
```

세 가지 문제가 있다.

1. **상대 거리 `j−i` 가 네 항에 흩어진다.** 모델이 학습으로 짜맞춰야 한다.
2. **내용 벡터가 실제로 이동한다.** `‖x_t + p_t‖ ≠ ‖x_t‖` — 위치가 의미 공간을 오염시킨다.
3. **외삽이 안 된다.** learned 방식은 학습 길이를 넘으면 `p_t` 자체가 없다.

> **방향 전환: 더하지 말고, 돌리자.** 회전은 길이를 보존한다.

## 2-3. RoPE 유도 — 요구에서 함수를 역산한다

**요구사항을 그대로 식으로 쓴다.**

```
찾아라: 함수 f 로서
        ⟨ f(q, m), f(k, n) ⟩ = g(q, k, m − n)
                                        └─ m, n 이 따로 나타나면 안 된다
```

**2차원으로 줄여 푼다.** `q = (q_0, q_1)` 을 복소수 `z_q = q_0 + i q_1` 로 본다.
이때 실벡터 내적은 복소수로 이렇게 쓰인다:

```
⟨a, b⟩ = a_0 b_0 + a_1 b_1 = Re( z_a · conj(z_b) )
```

(확인: `z_a conj(z_b) = (a_0+ia_1)(b_0−ib_1) = (a_0b_0+a_1b_1) + i(a_1b_0−a_0b_1)`.
실수부가 정확히 내적이다.)

이제 **`f(q, m) = z_q · e^{imω}`** 로 놓아 본다 — 크기는 그대로 두고 각도만 `mω` 돌린다.

```
⟨f(q,m), f(k,n)⟩ = Re( z_q e^{imω} · conj( z_k e^{inω} ) )
                 = Re( z_q e^{imω} · conj(z_k) e^{−inω} )
                 = Re( z_q conj(z_k) · e^{i(m−n)ω} )
```

**`m − n` 만 남는다.** 요구가 정확히 충족된다. ∎

그리고 `|e^{iθ}| = 1` 이므로

```
‖f(q,m)‖ = ‖q‖        ← 길이 보존. 내용을 오염시키지 않는다
```

**실수 행렬로 다시 쓰기.** `e^{imω}` 곱은 2차원 회전행렬이다.

```
R_m = [ cos mω   −sin mω ]
      [ sin mω    cos mω ]
```

필요한 성질은 회전의 군(group) 구조다.

```
R_mᵀ = R_{−m}          (회전의 역은 반대 방향 회전)
R_a R_b = R_{a+b}      (돌리고 또 돌리면 각도가 더해진다)

⟹  (R_m q)ᵀ (R_n k) = qᵀ R_mᵀ R_n k = qᵀ R_{−m} R_n k = qᵀ R_{n−m} k
```

같은 결론이다.

> **RoPE 는 "발명"이 아니라 요구사항의 유일한 자연해다.**
> 길이를 보존하면서 내적이 상대 위치에만 의존하게 하는 변환은 회전밖에 없다
> (2차원 직교군의 회전 성분).

## 2-4. 왜 주파수를 여러 개 쓰나

`d = 128` 을 **64개의 2차원 평면**으로 쪼개고, 평면마다 다른 각속도를 준다.

```
        ┌ R(m ω_0)                     ┐
R_m  =  │         R(m ω_1)             │      블록 대각 (64개 블록)
        │                 ⋱            │
        └                    R(m ω_63) ┘

ω_j = base^(−2j/d),    base = 10000,    j = 0 … 63
```

블록 대각이므로 `R_mᵀR_n = R_{n−m}` 이 **블록마다 그대로 성립**한다. 따라서

```
q̃ᵀk̃ = Σ_{j=0}^{63} Re( z_q^{(j)} conj(z_k^{(j)}) · e^{i(m−n)ω_j} )
```

— 전 차원에서 상대 거리에만 의존한다.

**주파수를 하나만 쓰면 안 되나.** 안 된다. 파장

```
λ_j = 2π / ω_j = 2π · 10000^{2j/d}
```

마다 위치가 **반복**되기 때문이다(aliasing). `λ = 6.3` 인 평면만 쓰면
거리 7 과 거리 1 을 구분할 수 없다.

여러 주파수를 기하급수적으로 배치하면 위치가 **여러 자릿수로 동시에** 표현된다.

```
j = 0   : λ ≈ 6.3        인접 토큰 분해능 (고주파)
j = 32  : λ ≈ 628
j = 63  : λ ≈ 62,800     문서 스케일 (저주파)
```

시계의 초침·분침·시침, 혹은 수의 자릿수 표기와 같은 구조다.

**부수 효과 — long-term decay.** 주파수가 다른 항들의 합이므로, 거리 `|m−n|` 이
커지면 위상이 흩어져 서로 상쇄되고 내적의 기대 크기가 **평균적으로 감소**한다.
"멀수록 관련이 적다"는 귀납 편향이 공짜로 따라온다. 단조 감소는 아니다.

**컨텍스트 확장 기법은 전부 `ω_j` 를 건드리는 것이다.** 길이를 `s` 배로 늘릴 때:

| 기법 | 조작 | 논리 |
|---|---|---|
| Position Interpolation | 위치 압축 `m → m/s` | 학습 때 본 각도 범위 안에 머문다. 대신 **고주파 해상도가 `s` 배 뭉개진다** |
| NTK-aware | base 증가 `10000 → 10000·s^{d/(d−2)}` | 저주파만 늘리고 고주파는 거의 유지 |
| YaRN | 파장별 차등 + attention 온도 보정 | `λ_j ≪ L_train` 은 그대로, `λ_j ≫ L_train` 만 보간 |

공통 원리: **파장이 학습 길이보다 짧은 평면은 이미 여러 주기를 봤으니 외삽해도 안전하고,
긴 평면은 한 주기도 못 봤으니 외삽하면 미지 영역이다.** 후자만 보간한다.

## 2-5. 왜 V 에는 걸지 않나

위치가 필요한 곳과 필요 없는 곳이 정확히 갈린다.

```
"어디를 볼 것인가"   :  s_ij = q̃_i · k̃_j        ← 위치 필요   ✔ Q, K
"무엇을 가져올 것인가" :  out_i = Σ_j a_ij v_j     ← 위치 불필요  ✘ V
```

`V` 를 회전시키면

```
out_i = Σ_j a_ij R_{jω} v_j
```

가 되어 **출력 벡터 자체가 위치에 따라 뒤틀린다.** 그 값은 residual stream 에
더해져 다음 레이어로 흐르므로 의미 표상이 오염된다. 게다가 `j` 마다 회전각이 달라
2-3 의 상쇄 성질도 성립하지 않는다.

> **설계 원칙: 위치는 가중치를 정하는 데만 쓰고, 운반되는 내용에는 넣지 않는다.**

## 2-6. 구현 — 두 가지 페어링

수학은 `(x_0,x_1), (x_2,x_3), …` 를 짝짓지만 구현은 두 갈래다.

```
▸ interleaved  (원논문, llama.cpp 계열, distributed-llama)
    짝 : (0,1), (2,3), …, (126,127)

▸ half-split / rotate_half  (HuggingFace Llama)
    짝 : (0,64), (1,65), …, (63,127)
    rotate_half(x) = [ −x[64:] ; x[:64] ]
    out = x ⊙ cos + rotate_half(x) ⊙ sin
```

두 방식은 **head 차원의 순열만큼 다르다.** 수학적으로 동치이지만
**`W_q`, `W_k` 를 그 순열에 맞게 재배열해 두어야** 한다
(HF 변환 스크립트의 `permute()` 가 이 작업이다).

> 이게 틀리면 **모델이 죽지 않고 조용히 품질만 떨어진다.**
> [04-concepts §4-4](04-concepts.md#4-4-simd-와-내적-명령어) 의 dotprod 플래그와
> 같은 종류의 함정이다 — "돌아간다"와 "제대로 돌아간다"가 다르다.
> 엔진 간 가중치 변환이나 KV 교환을 할 때 반드시 확인한다.

실무 구현은 `cos/sin` 을 매번 계산하지 않고 `(max_seq_len, d/2)` 테이블로 미리 만든다.
prefill 은 이 테이블을 broadcast 로 읽는다 — 연산량은 무시할 수준이다.

# 3부. KV 캐시

## 3-1. 캐시 여부를 결정하는 기준

기준은 하나다.

> **그 텐서가 미래 스텝에서 다시 읽히는가?**

새 토큰 `t` 가 도착했을 때 필요한 것을 전부 적어 본다.

```
s_tj  = q̃_t · k̃_j        j = 0 … t      →  과거의 k̃_j 전부 필요        ✔
out_t = Σ_j a_tj v_j                    →  과거의 v_j 전부 필요        ✔
q̃_j  (j < t)                            →  어디에도 나타나지 않는다     ✘
a_ij  (i < t)                            →  나타나지 않는다             ✘
```

`q̃_j` 는 자기 행의 attention 을 계산할 때 한 번 쓰이고 역할이 끝난다.
causal mask 때문에 **과거 토큰의 출력은 미래 토큰이 추가돼도 절대 바뀌지 않으므로**
다시 계산할 일이 없다([04-concepts §1-4](04-concepts.md#1-4-causal-mask)).

```
캐시 없음 : 스텝 t 마다 K,V 를 t+1 개 계산  →  Σ_t (t+1) = O(S²)
캐시 있음 : 스텝마다 1개만 계산해 덧붙임      →  O(S)
```

## 3-2. 왜 "회전 후"의 K 를 저장하나

두 선택지를 비교한다.

| | 저장 내용 | decode 시 추가 연산 | 저장량 |
|---|---|---|---|
| **(A)** | `k̃_j = R_{jω} W_k φ(x_j)` | **0** — 그냥 내적 | 동일 |
| (B) | `k_j = W_k φ(x_j)` | 매 스텝 × 모든 `j` × 모든 레이어에 `R` 재적용 | 동일 |

(B) 의 추가 비용은 스텝마다 `S × L × kvDim` 이다. 회전은
**위치가 확정되면 다시 바뀌지 않는 결정론적 후처리**이므로 한 번만 해두면 된다.
그래서 모든 엔진이 (A) 를 쓴다.

**대가: 캐시가 위치에 못 박힌다(position-baked).**

| 하고 싶은 것 | 가능한가 |
|---|---|
| 공통 접두사(system prompt) 캐시 재사용 | ✅ 위치 0 부터 동일 → 회전각도 동일 |
| 캐시 블록을 **다른 위치**에 재사용 | ❌ `R_{−mω}` 로 되돌리고 `R_{m′ω}` 재적용 필요 |
| 중간에 토큰 삽입 | ❌ 뒤쪽 전체의 회전각이 밀린다 |

> vLLM 의 automatic prefix caching 이 **접두사에만** 적용되고 임의의 부분열에는
> 적용되지 않는 이유가 이것이다. 이를 정면으로 푸는 것이 CacheBlend / EPIC 계열
> (회전 재적용 + 일부 재계산)이다.

## 3-3. 크기 공식 유도

토큰 1개 · 레이어 1개에서 저장하는 것은 `k̃` 와 `ṽ`, 각각 `kvDim` 개 원소다.

```
토큰1·레이어1  =  2 × kvDim × dtype_bytes
                 └─ K 와 V

전체           =  2 × L × kvDim × S × batch × dtype_bytes
                 = 2 × L × n_kv × d × S × batch × dtype_bytes
```

Llama-3-8B (`L=32, n_kv=8, d=128 → kvDim=1024`):

| dtype | 레이어당 | 토큰당 | S=2048 | S=448 (이 프로젝트) |
|---|---|---|---|---|
| F32 | 8 KB | 256 KB | 512 MB | 112 MB |
| F16 | 4 KB | 128 KB | 256 MB | 56 MB |

> [04-concepts §2-2](04-concepts.md#2-2-kv-캐시) 의 512 MB 는 F32 기준이다.
> 외부 문헌의 256 MB 는 F16 기준이다. **같은 식의 두 정밀도**이므로 인용할 때 명시한다.

**식에서 읽어야 할 것:**

```
h(=4096) 는 들어가지 않는다.        ← 모델 폭이 아니라
n_kv(=8) 가 들어간다.               ← KV 헤드 수가 크기를 정한다
```

그래서 **GQA 가 유일하게 효과적인 구조적 레버**다
([04-concepts §2-4](04-concepts.md#2-4-mha--mqa--gqa)). 그리고 분산 관점에서:

```
토큰 축(CP)으로 나눌 때 노드 간 교환량 ∝ kvDim = 1024,  h = 4096 이 아니다
→ GQA 가 CP 통신을 4배 싸게 만든다
```

## 3-4. 이 프로젝트와의 연결

[04-concepts §2-5](04-concepts.md#2-5-ttft) 는 "TTFT 시점에 만들어져야 하는 것은
전 토큰·전 레이어의 KV + 마지막 토큰의 로짓뿐"이라고 정리했고,
[7부](04-concepts.md#7부-계산을-건너뛰기--선형대수) 는 그 KV 를 더 싸게 만드는 방향을 다룬다.

RoPE 관점에서 여기에 붙는 결론이 하나 있다.

> **근사·예측의 대상은 반드시 회전 전 `k_j = W_k φ(x_j)` 여야 한다.**

이유가 셋이다.

**① `k̃_j` 는 위치의 함수라 회귀 타깃으로 부적합하다.**
같은 내용이 위치마다 다른 벡터가 되므로, 학습해야 할 사상이
"내용 사상 + 회전"으로 뒤섞인다. 회전을 빼면 순수한 내용 사상만 남는다.

**② 회전은 직교 변환이라 오차 크기를 보존한다.**

```
‖R(k − k̂)‖ = ‖k − k̂‖              (R 이 직교행렬이므로)
```

따라서 회전 **전**에서 잰 상대 오차가 회전 **후**에도 그대로 성립한다
([04-concepts §8-1](04-concepts.md#8-1-상대-오차)).
근사 오차 분석이 위치와 무관하게 성립한다는 뜻이고, 이는 꽤 강한 보증이다.

**③ 회전은 거의 공짜다.** `kvDim` 에 선형이고 행렬 곱이 없다. 근사할 대상이 아니다.

**분산 구현에서의 주의**: 토큰 축을 나눌 때(CP, 블록 병렬, 그리고
[10-design-prune-pipeline](../10-design-prune-pipeline.md) 의 압축 경로)
각 노드·각 행은 **전역 position id 를 정확히 유지해야 한다.**
압축 후 행 번호로 위치를 다시 매기면 상대 거리가 전부 틀어진다 —
근사 오차가 아니라 그냥 버그다. 10 §3-2 가 "`positions` 파이프도 함께 압축하되
원래 위치를 유지해야 RoPE 와 attention 이 맞는다"고 적은 것이 이 조건이다.

# 4부. 쪼개고 합치기

[04-concepts §3-7](04-concepts.md#3-7-online-softmax) 과
[§6-3](04-concepts.md#6-3-lse-merge--부분-attention-을-정확히-합치는-법) 은 직관을 준다.
여기서는 **정확성을 증명**한다. 이 증명이 있어야 "exact 하다"는 주장을 할 수 있다.

## 4-1. online softmax 가 정확한 이유

**주장**: 블록 단위로 누적한 결과가 한 번에 계산한 것과 **비트 수준의 반올림을 제외하고 동일**하다.

점수 집합 `{s_j}` 를 두 블록 `J_1, J_2` 로 나눈다. 각 블록에서 국소 최대값
`m_p = max_{j∈J_p} s_j` 를 빼고 계산한다.

```
ñ_p = Σ_{j∈J_p} e^{s_j − m_p} v_j          (부분 분자)
d̃_p = Σ_{j∈J_p} e^{s_j − m_p}              (부분 분모)
```

전체 최대값 `m = max(m_1, m_2)` 로 기준을 옮긴다. 0-3 의 지수 성질에서

```
e^{s_j − m} = e^{s_j − m_p} · e^{m_p − m}
```

이고 `e^{m_p − m}` 은 블록 안에서 **`j` 와 무관한 상수**이므로 합 밖으로 나온다.

```
Σ_{j∈J_p} e^{s_j−m} v_j = e^{m_p−m} · ñ_p
Σ_{j∈J_p} e^{s_j−m}     = e^{m_p−m} · d̃_p
```

따라서

```
out = ( e^{m_1−m} ñ_1 + e^{m_2−m} ñ_2 ) / ( e^{m_1−m} d̃_1 + e^{m_2−m} d̃_2 )
```

이고, 이는 정의대로 계산한 `Σ_j e^{s_j−m} v_j / Σ_j e^{s_j−m}` 과 같다. ∎

**두 가지가 동시에 성립한다는 점이 핵심이다.**

1. **수치 안정**: 모든 지수의 인자가 `≤ 0` 이라 오버플로가 없다.
2. **정확성**: 기준점 이동이 분자·분모에 같은 상수를 곱하므로 결과가 불변이다(0-3 ②).

**따라오는 것**: `S × S` 점수 행렬을 메모리에 쓰지 않아도 된다.
이것이 FlashAttention 의 근거이고, 이 프로젝트의 융합 커널
(`multiheadAttFused_F32`, [06 §4.8](../06-baseline-status.md))이 하는 일이다.

> 다만 **온라인 소프트맥스 자체는 이 프로젝트에서 속도를 개선하지 않았다.**
> [12-findings #7](../12-findings.md) 에 기록된 대로, B=448 의 병목은 점수 행렬
> 실체화가 아니라 **쿼리 워킹셋**이었고, 쿼리 축 타일(`BR=32`)을 추가하고 나서야
> 16배가 나왔다. 온라인 소프트맥스의 값어치는 **속도가 아니라 아래 4-2 를 여는 것**이다.

## 4-2. LSE merge 의 정확성 증명

4-1 에서 `J_1, J_2` 는 **같은 기계 안의 두 블록**이었다. 그런데 증명 어디에도
"같은 기계"라는 가정이 없다.

> **따라서 `J_1` 을 노드 1이, `J_2` 를 노드 2가 계산해도 결론이 그대로 성립한다.**

교환해야 할 것은 블록마다 세 개뿐이다.

```
ñ_p  : 부분 출력      (d = headDim 개 float)
d̃_p  : 부분 분모      (1개)
m_p  : 국소 최대값     (1개)
```

`(d̃_p, m_p)` 를 `LSE_p = m_p + log d̃_p` 하나로 묶어 주고받으므로 **LSE merge** 라 한다.

```
노드당 · 레이어당 · 헤드당 교환량 = (headDim + 1) float = 129 × 4B ≈ 516 B
```

전체 KV(수십~수백 MB)에 비하면 **사실상 공짜**다.

**의미:**

> **KV 를 한 곳에 모을 필요가 없다. 흩어진 채로 두고 부분 결과만 합치면 되고,
> 그 병합은 근사가 아니라 exact 하다.**

이것이 Ring CP([09](../09-design-ring-cp.md)), 블록 병렬의 최종 merge,
토큰 축 decode 를 모두 성립하게 하는 공통 기반이다.

**단, 이 프로젝트에서는 실제로 쓰지 않았다.** [09 §3](../09-design-ring-cp.md) 이
적은 대로, dllama 의 KV 버퍼가 이미 전체 `seqLen` 을 갖고 있어 **받은 KV 를 제자리에
써 넣고 기존 커널을 그대로 돌리는 편**이 단순하고 수학적으로도 단일 노드와 동일하다.
LSE merge 는 "KV 버퍼를 공유할 수 없을 때"의 도구다.

그리고 Ring CP 자체가 [11-results §7](../11-results.md) 에서 보류됐다 —
통신량이 PP 의 8배(168 vs 21 MB)여서다. **정확성이 보장된다고 채택 이유가 되지는 않는다.**

## 요약

| 질문 | 답 |
|---|---|
| 왜 Q·K 를 분리하나 | 점수 함수를 **비대칭** 이중선형 형식 `φ(x)ᵀMφ(x)` 로 만들기 위해. `M = W_qᵀW_k` |
| 왜 V 를 분리하나 | "찾아지는 방식"과 "전달할 내용"이 다른 정보라서 |
| `√d` | softmax 입력의 **표준편차를 1로** 맞추는 상수. `Var[q·k] = d` 이므로 |
| `d_head` 의 또 다른 의미 | 점수 함수 `M` 의 **랭크 상한** |
| 왜 위치 인코딩이 필요한가 | `Attn(PX) = P·Attn(X)` — 인코딩이 없으면 집합 함수다 |
| RoPE 는 어떻게 나왔나 | `⟨f(q,m),f(k,n)⟩ = g(q,k,m−n)` 요구의 자연해. 2차원 회전 |
| 왜 회전인가 | **길이를 보존**하면서 내적이 상대 위치에만 의존하는 유일한 변환 |
| 왜 주파수가 여럿인가 | 단일 주파수는 파장마다 위치가 반복(aliasing). 다중 해상도 표현이 필요 |
| 왜 V 에는 안 거나 | 회전하면 출력이 뒤틀려 residual stream 을 오염시킨다 |
| 왜 K,V 만 캐시하나 | 미래 스텝이 다시 읽는 것이 K,V 뿐. Q 는 자기 행에서 소비되고 끝 |
| 왜 회전 후를 저장하나 | 회전은 결정론적 후처리라 한 번만 하면 된다. 대가는 **위치 고정** |
| KV 크기를 정하는 것 | `h` 가 아니라 `n_kv`. 그래서 GQA 가 유일한 구조적 레버 |
| 근사의 타깃 | **회전 전** `k = W_kφ(x)`. 직교 변환이라 오차가 보존된다 |
| 부분 병합이 exact 한 이유 | 기준점 이동이 분자·분모에 **같은 상수**를 곱하기 때문 |
