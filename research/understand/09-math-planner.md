## 1부. 문제가 무엇인가

### 1-1. 처음부터: prefill 을 왜 나누나

프롬프트 `S` 토큰을 Transformer 에 통과시켜 KV 캐시를 만드는 것이 prefill 이다.
레이어가 32개고 노드가 8대면 이렇게 나눌 수 있다.

```text
node0: layer  0.. 3
node1: layer  4.. 7
...
node7: layer 28..31 + lm_head
```

그런데 프롬프트 전체를 한 덩어리로 밀면 `node0` 이 일하는 동안 나머지 7대가 논다.
그래서 `S` 를 폭 `B` 의 조각(마이크로배치)으로 나눠 흘린다.

```text
S=128, B=32  →  M = 4

시간 →     t0    t1    t2    t3    t4    t5    t6
stage0     mb0   mb1   mb2   mb3
stage1           mb0   mb1   mb2   mb3
stage2                 mb0   mb1   mb2   mb3
stage3                       mb0   mb1   mb2   mb3
```

`mb0` 이 stage1 로 넘어가면 stage0 은 `mb1` 을 시작한다. 이것이 파이프라인 겹침이다.

### 1-2. 고르는 것이 세 개다

| 기호 | 무엇 | 왜 자유변수인가 |
|---|---|---|
| `N` | 쓸 스테이지 수 | 짧은 입력에 노드를 많이 쓰면 fill/drain 이 커진다 |
| `B` | 마이크로배치 폭 | 작으면 커널 효율이 나쁘고, 크면 `M` 이 줄어 버블이 커진다 |
| `p` | 서브블록 경계 | 노드마다, 연산자마다 속도가 다르다 |

`p` 는 `0 = p_0 < p_1 < ... < p_N = L` 인 경계다. 스테이지 `k` 가 `[p_k, p_{k+1})` 를 맡는다.
32 레이어를 att/ff 로 쪼개면 `L = 64` 다.

### 1-3. 탐색 공간이 왜 큰가

연속 분할만 세어도

```text
C(L-1, N-1) = C(63, 7) ≈ 5.5 × 10^8
```

각 후보를 **실제로 실행해 보는 것**(end-to-end sweep)은 불가능하다.
그래서 비용을 **계산**해야 하고, 계산하려면 비용 모델이 있어야 한다.

> 이것이 DerivePP 의 출발점이다: **탐색이 아니라 유도.**

## 2부. 고전식은 어디까지 맞나

### 2-1. 모든 것이 같을 때

스테이지 시간이 전부 `c` 로 같고 통신이 0 이면

```text
직렬       = M·N·c
파이프라인 = (M + N − 1)·c
속도향상   = M·N / (M + N − 1)
버블       = (N − 1) / (M + N − 1)
```

`N=8, M=64` 면 버블 `7/71 = 9.9 %`. 직관을 주는 좋은 식이다.

### 2-2. 조금 완화: 스테이지마다 다를 때

스테이지 시간이 `t_k` 로 다르면(마이크로배치끼리는 같다면)

```text
T = Σ_k t_k + (M − 1)·max_k t_k
    └ fill ┘   └ steady state ┘
```

첫 마이크로배치가 모든 스테이지를 통과하는 데 `Σ t_k`,
그 뒤로는 가장 느린 스테이지 속도로 배출된다.

여기서 이미 중요한 것이 보인다.

```text
M 이 작으면  → Σ t_k 가 중요       → 합을 줄이는 분할
M 이 크면    → max t_k 가 중요     → 균형 잡는 분할
```

**짧은 입력과 긴 입력에서 최적 분할이 다른 이유**가 여기서 나온다.

### 2-3. 그런데 causal prefill 은 이 가정을 깬다

마이크로배치 `j` 는 KV `[0, jB)` 를 본다. 뒤로 갈수록 비싸다.

```text
mb0 : 자기 앞 토큰만
mb1 : B 개 더
...
mb(M−1) : 거의 전체 프롬프트
```

즉 `t_{k,0} ≠ t_{k,1} ≠ ... ≠ t_{k,M−1}` 이다.
`Σ + (M−1)max` 식은 **더 이상 정확하지 않다.**

여기에 더해

- 노드가 이종이다 (같은 Pi5 인데 1.6배 차이)
- 링크가 이종이다 (스위치 군 간 100 Mb, 군 내 1 GbE)
- 마지막 청크는 폭이 `B` 보다 작을 수 있다

## 3부. 완료시각 recurrence

### 3-1. 정의

`F_{k,j}` = 스테이지 `k` 가 마이크로배치 `j` 를 **끝낸** 시각.

스테이지 `k` 가 `j` 를 시작하려면 두 조건이 **모두** 만족되어야 한다.

```text
(a) 앞 스테이지가 j 를 끝내고 전송까지 마쳤다:  F_{k−1,j} + D_k(j)
(b) 이 스테이지가 j−1 을 끝냈다:                F_{k,j−1}
```

따라서

```text
F_{k,j} = max( F_{k−1,j} + D_k(j),  F_{k,j−1} ) + C_{k,j}

초기: F_{k,−1} = 0,  F_{−1,j} = 0
답:   T = F_{N−1, M−1}
```

### 3-2. 통신이 안에 있어야 하는 이유

`+ comm` 을 마지막에 한 번 더하면 세 가지를 잃는다.

```text
느린 링크가 어느 경계에 있는지
통신이 실제로 다음 스테이지 도착을 늦췄는지
다른 마이크로배치 계산과 겹쳤는지
```

우리 클러스터는 스위치 군 간이 10배 느리다. 그 링크를 파이프라인 어디에 두느냐가
실제로 문제가 되므로, `D_k(j)` 는 recurrence 안에 있어야 한다.

### 3-3. 특수 경우로 환원된다

`C_{k,j} = C_k` (위치 독립), `D = 0` 이면

```text
F_{N−1,M−1} = Σ_k C_k + (M−1)·max_k C_k
```

즉 §2-2 의 고전식이 이 recurrence 의 특수해다. **일반화가 맞다는 확인**이 된다.

### 3-4. 닫힌 형태 — 벡터화의 근거

`j` 에 대한 순차 루프를 없앨 수 있다. `a_j = F_{k−1,j} + D_j + C_j`,
`C^Σ_j = Σ_{i≤j} C_i` 로 두면

```text
F_{k,j} = C^Σ_j + max_{i ≤ j} ( a_i − C^Σ_i )
```

증명은 `j` 에 대한 귀납이다.

```text
j=0:  F_0 = a_0 = C^Σ_0 + (a_0 − C^Σ_0)                      ✓
j>0:  F_j = max(a_j, F_{j−1} + C_j)
          = max(a_j, C^Σ_{j−1} + max_{i≤j−1}(a_i − C^Σ_i) + C_j)
          = max(a_j, C^Σ_j + max_{i≤j−1}(a_i − C^Σ_i))
          = C^Σ_j + max( a_j − C^Σ_j, max_{i≤j−1}(a_i − C^Σ_i) )
          = C^Σ_j + max_{i≤j}(a_i − C^Σ_i)                    ✓
```

우변은 **prefix max** 다. `numpy.maximum.accumulate` 한 번이면 된다.
`M` 이 900 을 넘으면 Python 순차 루프로는 플래너가 끝나지 않으므로 이 형태가 실용상 필수다.

## 4부. DP 와 지배 가지치기

### 4-1. 왜 스칼라 DP 로 안 되나

분할을 왼쪽부터 정한다고 하자. 스테이지 `k` 까지 정했을 때 남는 정보가 무엇인가?

`Σ`(합)만 들고 가면 안 된다. `max` 가 섞여 있기 때문이다.
`max` 만 들고 가도 안 된다. fill 이 합에 의존하기 때문이다.

일반적으로 **완료시각 벡터 전체** `F_{k,·} ∈ ℝ^M` 가 필요하다.
이것이 이 문제를 보통의 min-max 분할 DP 와 다르게 만든다.

### 4-2. 상태와 전이

```text
DP[i] = 앞 i 개 서브블록을 지금까지의 스테이지에 배정했을 때
        도달 가능한 완료벡터의 집합
```

스테이지 `k` 가 `[i, e)` 를 맡으면, 각 상태 벡터 `v` 에 대해

```text
new_j = max(v_j + D_j, new_{j−1}) + C_j(i, e)
```

를 계산해 `DP[e]` 에 넣는다.

### 4-3. 지배 (보조정리 1)

**정의.** `A ⪯ B  ⟺  A_j ≤ B_j` 모든 `j` 에 대해.

**보조정리.** `A ⪯ B` 이면, 임의의 동일한 후속 배정을 적용한 결과도 `A' ⪯ B'` 이다.

*증명.* `A'_j = max(A_j + D_j, A'_{j−1}) + C_j`. `j` 에 대한 귀납.

```text
j=0:  A'_0 = A_0 + D_0 + C_0 ≤ B_0 + D_0 + C_0 = B'_0
j>0:  귀납가정 A'_{j−1} ≤ B'_{j−1}, 가정 A_j ≤ B_j 로부터
      max(A_j + D_j, A'_{j−1}) ≤ max(B_j + D_j, B'_{j−1})
      양변에 C_j 를 더하면 A'_j ≤ B'_j                        ∎
```

**따름정리.** 지배당하는 벡터를 버려도 최적해를 잃지 않는다.

이것이 DP 를 성립시키는 유일한 근거다. 이 성질이 없으면 모든 분할을 열거해야 한다.

### 4-4. 실제로 맞는지 확인했다

`L=8` 로 줄인 인스턴스에서 **모든 연속 분할을 전수 평가**한 값과 대조했다.

```text
N=2 B=16   DP 1446.086 ms   BF 1446.086 ms   일치
N=2 B=32   DP 1400.616      BF 1400.616      일치
N=3 B=16   DP 1141.462      BF 1141.462      일치
N=3 B=32   DP 1134.173      BF 1134.173      일치
N=4 B=16   DP 1059.326      BF 1059.326      일치
N=4 B=32   DP  914.132      BF  914.132      일치
```

증명과 실증이 둘 다 있는 상태다.

> **주의**: 이 대조가 유효하려면 DP 와 brute force 가 **같은 비용 소스**를 써야 한다.
> 한 번 이것을 어겨 6/6 불일치가 났고, 원인은 알고리즘이 아니라
> DP 는 executor 캘리브레이션을, brute force 는 op 단위를 쓰고 있던 것이었다.
> 그래서 비용 진입점을 `costs_for_nodes()` 하나로 모았다.

## 5부. 복잡도와 실제 성능

### 5-1. 이론

| | |
|---|---|
| 상태 수 | `O(N·L)` |
| 상태당 전이 | `O(L)` 개 구간 × frontier 크기 `Φ` |
| 벡터 갱신 | `O(M)` |
| **전체** | **`O(N·L²·Φ·M)`** |

`Φ` 는 이론적으로 크게 잡히지만 실측은 수백~수천이다.

```text
M=57  → Φ ≈ 1,088
M=76  → Φ ≈   970
M=113 → Φ ≈ 3,084
```

**지수적으로 폭발하지 않는다.** 그래서 exact DP 를 그대로 쓸 수 있고,
top-K fallback 이 필요 없다. 이 관측 자체가 보고할 결과다.

### 5-2. 성능 벽 — 세 번 잘못 짚었다

실규모(`M=451`)에서 계획 생성이 40분에도 끝나지 않았다.

| 시도 | 근거 | 결과 |
|---|---|---|
| `M` 순차 루프 벡터화 | prefix max 닫힌 형태 | 필요했지만 부족 |
| 상태를 `(Φ,M)` 행렬로 | numpy 호출 수 `Φ` 배 감소 | 필요했지만 부족 |
| 비용 계산 닫힌 식 + 캐시 | `stage_cost` 가 `O(e−i)` | 필요했지만 부족 |
| **프로파일링** | — | **`np.asarray` 629 k 회 = 92 s 중 63 s** |

지배 가지치기가 `kept` 리스트를 **매 후보마다 배열로 재구성**하고 있었다(`O(Φ²·M)` 복사).
미리 할당하고 뷰로 비교하자 4배 빨라졌다.

> **교훈**: 성능 문제도 측정으로 접근해야 한다. 세 번 연속 추측이 빗나갔다.

### 5-3. 지금 쓰는 세 가지 닫힌 식

```text
F_j = C^Σ_j + max_{i≤j}(a_i − C^Σ_i)          recurrence (§3-4)
n_att(a,b) = ((b−a) + [a 짝수]) // 2           구간 내 att 개수
kept 는 미리 할당하고 뷰로 비교                  O(Φ²M) 복사 제거
```

## 6부. 비용 oracle 의 모양

### 6-1. DP 는 비용의 **형태**에 의존하지 않는다

recurrence 는 `C_{k,j}(a,b)` 를 블랙박스로 쓴다. 따라서

```text
비용 모델이 바뀌어도 DP recurrence 는 바뀌지 않는다.
```

이것이 중요하다. 캘리브레이션을 네 번 갈아엎는 동안 DP 는 한 번도 안 바뀌었다.

### 6-2. 그러나 **분해 가능성**은 필요하다

DP 는 임의의 연속 구간 `[a,b)` 비용을 물어본다. 그래서 두 방식 중 하나여야 한다.

```text
(가) 서브블록 단위로 분해:  C(a,b,j) = Σ_{r∈[a,b)} c_r(j)
(나) 구간 표를 직접 제공:   C[a,b,j]  (최대 L²/2 = 2,048 개)
```

지금은 (가)다. 다만 단순 합이 아니다.

### 6-3. stage-start 비용 — 단순 합이 깨지는 실제 사례

레이어별 실측에서 **layer 0 의 attention 이 나머지의 2배**다.

```text
Latt (B=32, prefix=8192), 8노드 전부
  L0 = 231~238 ms,  L1~L3 = 109~121 ms
  L0/평균 = 2.01~2.09배      (편차 4 %)
  Lff 에는 없음
```

매 forward 의 첫 attention 이 부담하는 비용(scratch cold-cache 로 추정)이다.
따라서

```text
틀림:  C_att(n) = n · mean(A_start, A_steady, A_steady, ...)
맞음:  C_att(n) = A_start + (n−1)·A_steady          (n ≥ 1)
```

평균을 쓰면 start 비용을 `n` 번 세게 된다. 그리고 이것이 실제로 예측에 영향을 줬다.

```text
S=7,212 N=1   평균 방식 892 s (비 0.80)  →  start/steady 794 s (비 0.71)
```

**정확도가 내려간 것이 옳은 방향이다.** 이전 0.80 은 start 를 32번 센 과대예측이
다른 과소예측과 상쇄된 결과였고, 모델을 고치자 가려져 있던 진짜 잔차가 드러났다.

> **일반 교훈**: 두 오차가 상쇄되면 총합은 맞아 보이지만 **분할 선택은 틀린다.**
> 스케줄러는 총합이 아니라 대안 간 순서를 필요로 하므로 이런 상쇄는 위험하다.

### 6-4. 두 종류의 정확성을 분리해야 한다

```text
예측 정확도:  MAPE   = |T_pred − T_meas| / T_meas
결정 정확도:  regret = T_meas(선택) / min_p T_meas(p) − 1
```

절대시간이 20 % 낮아도 그것이 **모든 계획에 공통인 배율 오차**이고 regret 가 작으면
스케줄러 기여는 유효하다. 반대로 절대 오차가 5 % 여도 잘못된 경계를 고르면 실패다.

논문에서는 이 둘을 반드시 따로 보고해야 한다.

## 7부. 흔한 오해

### 오해 1. "버블 공식으로 충분하다"

`(N−1)/(M+N−1)` 은 스테이지·마이크로배치 비용이 모두 같을 때만 맞다.
causal prefill 은 뒤 마이크로배치가 더 비싸고 노드도 이종이다.
고전식은 직관용이지 최종 비용식이 아니다.

### 오해 2. "`Σ + (M−1)max` 를 최소화하면 된다"

`M` 이 매우 클 때의 근사다. 짧은 입력에서는 fill(`Σ`)이 중요해지고,
그때 최적 분할이 달라진다. 그리고 위치 의존 비용을 표현하지 못한다.

### 오해 3. "지배 가지치기는 휴리스틱이다"

보조정리 1 이 있으므로 **최적해를 잃지 않는다.** 근사가 아니다.
단, 그 증명은 recurrence 가 각 성분에 대해 단조라는 성질에 의존한다.
비용 모델을 바꿔도 이 성질은 유지되지만, recurrence 형태를 바꾸면 다시 확인해야 한다.

### 오해 4. "`Φ` 가 이론적으로 크니 근사가 필요하다"

실측 `Φ` 는 수백~수천이다. 근사(top-K)를 넣으면 exact 보장이 깨지고,
그러면 "근사 때문에 틀렸나, 모델이 틀렸나"를 구분할 수 없게 된다.
**정확도를 먼저 확보하고 성능은 나중에** 다뤄야 하는 이유다.

### 오해 5. "예측이 실측과 가까우면 모델이 옳다"

§6-3 이 반례다. 평균 방식이 `0.80` 으로 더 가까웠지만 **물리적으로 틀렸고**,
그 상쇄는 조건이 바뀌면 무너진다. 총합 일치는 필요조건이지 충분조건이 아니다.

### 오해 6. "비용 모델을 바꾸면 DP 를 다시 설계해야 한다"

아니다. DP 는 `C_{k,j}(a,b)` 를 블랙박스로 쓴다.
비선형성이 확인되면 구간 표 `C[a,b,j]` 를 직접 주면 되고,
`L=64` 면 최대 `64²/2 = 2,048` 개라 prefix sum 으로 미리 계산할 수 있다.
**recurrence 는 그대로다.**
