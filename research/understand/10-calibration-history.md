# 캘리브레이션 구현사 — 네 번 갈아엎은 기록

[08-math-executor-calibration](08-math-executor-calibration.md) 은 **왜 executor 와
동형이어야 하는가**를 수학으로 세운다. 이 문서는 그 뒤에 실제로 무엇을 만들었고,
무엇이 틀렸고, 왜 갈아엎었는지를 순서대로 적는다.

각 단계마다 **무엇을 가정했는지**를 명시한다. 가정을 하나씩 제거하는 것이
이 여정의 전부였기 때문이다.

---

## 0. 캘리브레이션이 무엇을 해야 하나

플래너는 임의의 `(노드, 서브블록 구간, 마이크로배치)` 에 대해 비용을 물어본다.

```text
C_k,j(a,b) = 노드 k 가 서브블록 [a,b) 를 맡을 때 마이크로배치 j 를 처리하는 시간
```

이걸 **end-to-end 실행 없이** 만들어야 한다(그게 sweep-free 의 정의다).
따라서 짧은 마이크로벤치로 재고, 그 값으로 위 식을 합성한다.

문제는 "짧은 마이크로벤치"가 production 과 **같은 것을 재는가** 이다.
이 문서는 그 질문에 네 번 다르게 답한 기록이다.

---

## 1단계. op 단위 처리율 (`calibrate.cpp`)

### 무엇을 했나

커널 두 계열을 따로 재고 처리율을 만들었다.

```text
T_q(F, B)  = Q4×Q8 GEMM      →  P_q(B)  [FLOP/s]
T_a(F, B, prefix) = F32 attention core →  P_a(B, prefix)
```

그 다음 FLOPs 를 나눠 시간을 만든다.

```text
att 비용 = 4·b·d(d+d_kv) / P_q  +  4·d·A_j / P_a
ff  비용 = 6·b·d·d_ff / P_q
```

### 여기서 얻은 것 (지금도 유효)

- **`B_min = 16`** — `B ≤ 12` 는 처리율이 절반, `B ≥ 16` 은 포화.
  end-to-end 로 유도한 값과 독립적으로 일치했다.
- **`c(B)` 는 계단이다** — `B=24` 저하가 8/8 노드에서 재현된다.
  따라서 `B` 축은 **보간하면 안 되고** 최근접 격자를 써야 한다.
- **`ρ_k` 편차 23.6 %** — 노드별로 `P_q/P_a` 가 다르다. 공통 상수를 쓸 수 없다.
- ~~**연산자 순위 역전** — GEMM 최고 노드가 attention 최하위다(Kendall τ = −0.29).~~
  ⚠️ **철회.** 9노드 동시 수집 재측정에서 τ = +0.111 로 부호가 뒤집혔다.
  DVFS·열·메모리 대역폭·접근 지연 어느 것도 연산자 처리율과 상관되지 않았다.
  노드 간 처리율 편차 자체는 실재하나(GEMM 0.876~1.000, att 0.758~1.000)
  원인은 미규명이다. 상세는 `16-derivepp.md` §7.15.
  노드 이종성을 스칼라 하나로 표현할 수 없다는 직접 증거.

### 무엇이 틀렸나

production 대비 **−25 %** 과소예측. 성분별로도 균일했다(attnProj 0.82 / ffn 0.75 / attn 0.85).

특정 연산이 빠진 것이 아니었다. `normMs` 0.4 %, `otherMs` 4.4 % 로
RMSNorm·RoPE·residual·SwiGLU 를 다 더해도 2~4 % 다.

### 숨어 있던 가정

> **한 형상을 타이트 루프로 돌린 처리율이 실제 실행에도 적용된다.**

실제 커널은 레이어 안에서 여러 op 를 **교대로** 실행한다.
가중치가 서로를 캐시에서 밀어내고, op 경계마다 동기화가 붙고, 프리페처가 스트림을 잃는다.

## 2단계. 레이어 macrobench (`calibrate_layer.cpp`)

### 무엇을 바꿨나

op 를 하나씩 재는 대신 **transformer 레이어 하나를 실제 순서대로** 돌렸다.

```text
att 구간: RMSNorm → Q/K/V proj → RoPE → attention core → O proj → residual
ff  구간: RMSNorm → gate/up proj → SwiGLU → down proj → residual
```

핵심 설계 결정 하나: **시간을 FLOPs 로 나누지 않는다.**
나누는 순간 교대 효과가 다시 사라지기 때문이다.

### 결과

−25 % → **−22 %**. 0.7초만 메웠다.

### 여기서 기각한 가설

**가중치 working-set 가설**: "레이어 1개 가중치만 반복하면 DRAM 행 지역성이
실제보다 유리하다."

레이어 사본을 1 → 16 개(122 MB → 1,952 MB)로 늘려 봤다.

| 사본 | 1 | 2 | 4 | 8 | 16 |
|---|---|---|---|---|---|
| FFN ms | 20.90 | 20.07 | 20.90 | 20.89 | 22.19 |

**16배 늘려도 6 %.** 기각.

### 숨어 있던 가정 (그리고 코드 결함)

> **연산자를 교대시키면 production 과 같아진다.**

아니었다. 그리고 코드에도 결함이 있었다 — `Pool` 구조체와 "op 경계마다 배리어"라는
주석을 써놓고 **실제로 쓰지 않았다.** 각 스레드가 자기 op 열을 끝까지 독립 실행했다.

```text
배리어 있음: Σ_o max_t c_{o,t}      ← production
배리어 없음: max_t Σ_o c_{o,t}      ← 이 벤치
```

둘의 차이는 **빈 배리어 비용이 아니라 동기화가 노출하는 스레드 불균형**이다.

## 3단계. step tax 측정 (`bench_steps.cpp`) — 기각

### 질문

"배리어가 원인이면 얼마인가?"

실제 `NnExecutor` 에 1×1 CAST no-op step 을 `K` 개 넣고 `T(K) = a + h·K` 를 적합했다.
별도 barrier loop 가 아니라 production 의 atomic/yield 경로를 그대로 써야 한다.

### 결과

```text
h = 1.246 µs/step

FFN 384 step → 0.48 ms/chunk = 잔차 189 ms 의 0.3 %
잔차 전체 설명에 필요한 값 = 492 µs/step   (실측의 395배)
```

**순수 step 동기화는 원인이 아니다.** 기각.

작은 실측 항 `h` 자체는 보존한다(`X_k = n_step · h`).

### 부수 발견

`DLLAMA_DUMP_STEPS` 로 런타임 step 수를 세니 **레이어당 26개**(att 14 / ff 12)였다.
정적 카운트(조건부 op 포함)는 부정확하므로 런타임 값을 써야 한다.

### 구현 함정

`NnExecutorDevice` 는 `unique_ptr<NnDevice>` 로 **소유권을 가져간다.**
스택 객체 주소를 넘기면 소멸 시 delete 를 시도해 죽는다(ASan 으로 확인).

## 4단계. executor 동형 (`calibrate_exec.cpp`)

### 무엇을 바꿨나

production `buildLlmNet` 으로 그래프를 만들고 synthetic weight 를 주입한 뒤
실제 `NnExecutor::forward()` 를 돌렸다.

모델 파일이 필요 없고 `(N,B,p)` 를 end-to-end 로 쓸어보지도 않으므로
**sweep-free 정의는 유지**된다. 달라지는 것은 캘리브레이션이 executor 와 동형이 된다는 점뿐이다.

### 재현 시 필수인 두 가지

**1. `setDecodePhase(false)`**
설정하지 않으면 `lm_head` 가 decode 기본값으로 배치 전체 행을 계산한다(prefill 은 마지막 1행).
이것 하나로 실제의 1.5배가 나왔다.

**2. 레이어 수로 나누지 말 것**
그래프에는 embedding·final norm·lm_head 같은 레이어 무관 상수 `c0` 가 있다.
측정된 `c0` 는 19~70 ms 로 작지 않다.

### 결과

−22 % → **−18 %**. 그리고 여기서 중요한 정정이 나왔다.

### 정정 — 기준값이 콜드였다

`calibrate_exec` 와 production 을 **같은 세션에서 번갈아** 돌리자:

| 라운드 | production | calibrate_exec | 비 |
|---|---|---|---|
| r1 | 41.91 ms/layer | 30.65 | 0.73 |
| r2 | 36.89 | 31.08 | 0.84 |
| r3 | 34.58 | 31.69 | 0.92 |
| r4~r8 | 33.06 / 33.30 / 32.79 / 33.29 / 33.90 | — | — |

**production 만 단조 감소한다.** 4.5 GB 모델 파일의 페이지 캐시가 채워지는 과정이고,
콜드 41.9 → 웜 33.3 으로 17 % 차이다.

```text
production 콜드     41.9 ms   →  격차 −27 %
production 문서 최초 38.0     →  −18 %
production 웜        33.3     →  −6.0 %      ← 진짜 값
```

**분모가 14 % 부풀려져 있었다.** 이 정정으로 §1~§4 의 격차가 전부 바뀐다
(−25/−22/−18 → −14/−11/−6).

> **새 측정 규율**: 모델을 바꾼 뒤 첫 3회는 워밍업으로 버린다.
> `research/13` 의 "rep1 을 버린다"로는 부족하다.

### 그런데 플래너에 넣자 더 나빠졌다

`Lall`(레이어 전체)을 att/ff 로 쪼개야 DP 가 쓸 수 있는데, 그 분할을 상수 비율로 했다.

```text
att_share = 0.254     ← prefix ≈ 224 에서 잰 값
```

`S=7,212` 에서는 attention 비중이 훨씬 크다. 결과는 **−38~−52 % 과소예측과 순위 역전**.
op 단위 모델(−16~−20 %, 순위 적중)보다 나빠졌다.

> **교훈**: 측정을 정밀하게 만들어도, 그 출력을 DP 가 쓸 형태로 **가공하는 단계에서
> 새 가정을 넣으면** 이득이 통째로 되돌아간다.

### 가정 제거 — att/ff 를 직접 재기

`getLastForwardOpBreakdown()` 으로 production 의 `--stage-timing` 과 **같은 계측기**를 썼다.

```text
prefix:   128    512   2048   4096   8192
Latt:    6.73  11.07  14.88  24.18  48.26 ms   ← 7.2배 (O(S²))
Lff:    23.42  22.93  22.72  23.11  22.34 ms   ← 평평 (편차 4.6 %)
```

`Lff` 가 `prefix` 무관하게 평평한 것이 **분리가 올바르다는 직접 증거**다.
그리고 실제 `att:ff` 비율이 0.22 → 0.68 로 3배 변한다. 고정 비율이 왜 틀렸는지가 정량적으로 보인다.

## 5단계. 레이어별 직접 수집 (`calibrate_perlayer.cpp`) — 현재

### 왜 또 갈아엎었나

`calibrate_exec` 는 **레이어 수 회귀**로 레이어당 비용을 뽑는다(`T(L) = c0 + L·c_layer`).
이게 재현되지 않았다.

같은 조건(`root, B=32, prefix=8192`):

| 실행 | 조건 | 값 |
|---|---|---|
| 콜드 | 54 °C 시작, 짧음 | 103.6 ms |
| 웜 | 짧음 | 146.2 ms |
| 뜨거움 | 전체 45점 수집 | **302.5 ms** |

**2.9배.** 온도는 54 → 76 °C 로 올랐지만 주파수는 8 % 만 떨어졌다.
열은 기여하지만 지배 요인이 아니다.

### 결정적 실험 — 측정 시간을 늘리면 더 나빠진다

| inner | 시도1 | 시도2 | 시도3 | CV |
|---|---|---|---|---|
| 5 | 131.4 | 178.2 | 149.7 | 15 % |
| **40** | 174.2 | **92.6** | 116.2 | **32 %** |

랜덤 잡음은 줄지만 **체계적 편향이 커져** 순효과가 악화된다.

### 원인 — 루프 순서가 `L` 과 시간·온도를 함께 움직인다

```text
for prefix = 128 → ... → 8192      (뒤로 갈수록 뜨겁다)
  for B = 4 → ... → 128
    for L = 1 → 2 → 3 → 4          (뒤로 갈수록 뜨겁다)
```

`L=1` 은 차가울 때, `L=4` 는 뜨거울 때 측정된다.
회귀는 이 시간 드리프트를 **레이어 효과로 오인**한다.
`inner` 를 키우면 `L=4` 가 더 길고 더 늦게 돌아 교란이 커진다 — 위 표가 그것이다.

### 두 번째 구조적 결함

`normUs + otherUs` 를 att/ff 에 비례 배분했는데, 그 안에는

- 레이어 비례 항 (residual, cast, merge)
- **레이어 독립 항** (embedding, final norm, lm_head)

이 섞여 있다. 레이어 독립 항까지 배분하면 `ta/tf` 에 `c0` 가 다시 섞이고,
그 `c0` 를 회귀로 빼려 하니 스스로를 방해한다.

### 해법 — 한 forward 에서 레이어별로 읽는다

`NnExecutor::getLastForwardStepTimes()` 를 추가해 step 별 시간을 그대로 꺼낸다.
`opConfig->index` 가 `layerIndex` 이므로 레이어별로 모이고,
`block_` 접두가 없는 op(embedding, final, lm_head)는 자연히 `c0` 로 분리된다.

```text
제거된 것            대체
──────────────────────────────────────────────────────
레이어 수 회귀        한 forward 에서 모든 레이어를 같은 상태로 수집
rest 비례 배분        op 이름으로 att/ff/c0 직접 분류
c0 추정              layerIndex 로 자연 분리
R² 판정              적합을 안 하므로 불필요
lm_head op 단위 계산  측정된 c0 사용 (소스 혼용 제거)
```

### 정합성 검사가 내장된다

step 시간의 합은 forward 벽시계와 같아야 한다.

| prefix | 128 | 512 | 2,048 | 4,096 | 8,192 |
|---|---|---|---|---|---|
| stepsum / wall | 0.999 | 1.000 | 0.998 | 1.000 | 1.000 |

8노드 180행 전부 통과. **이 검사가 회귀에는 없었다.**
그래서 1.87배 과소한 값을 그대로 믿었다.

```text
prefix=128, B=32, L=4
  레이어별 직접:  0.534 s   (레이어당 ~169 ms + c0 48 ms)
  회귀 추정:      0.286 s   (레이어당 66 ms + c0 22 ms)   ← 1.87배 과소
```

### 그리고 layer 0 이 다르다

```text
Latt (B=32, prefix=8192), 8노드 전부
  L0 = 231~238 ms,  L1~L3 = 109~121 ms
  L0/평균 = 2.01~2.09배      (편차 4 %)
  Lff 에는 없음
```

**attention 에만, 8노드 전부에서** 재현된다. 랜덤 편차가 아니라
매 forward 의 첫 attention 이 부담하는 stage-start 비용이다.

```text
C_att(n) = A_start + (n−1)·A_steady      (n ≥ 1)
```

평균을 쓰면 start 비용을 `n` 번 세게 된다.

## 7. 아직 남은 가정

| 가정 | 왜 위험한가 | 검증 방법 |
|---|---|---|
| **`P = Q`** | 캘리브레이터는 `prefix = seqLen` 으로 고정한다. production 초기 청크는 `P ≪ Q` 다 | `Q=8192` 고정, `P ∈ {512,…,8192}` 소형 스윕 |
| **`c0` 가 마지막 스테이지에 있다** | PP 에서 embedding 은 stage 0, lm_head 는 stage N−1 이다. `N=1` 에서만 정확 | `PLc_in`/`PLc_out`/`PLc_common` 분리 출력 |
| **synthetic weight 가 실제와 같다** | Q4_0 값 분포가 다르면 denormal 등으로 타이밍이 달라질 수 있다 | 실제 가중치 일부로 대조 |
| **레이어 간 차이가 L0 뿐이다** | `L` 순서를 뒤집어 보지 않았다 | 정/역방향 교차 측정 |
| **수집 순서가 무해하다** | `prefix` 오름차순이라 `8192` 가 항상 가장 뜨겁다 | 순서 무작위화 + 주기적 anchor 재측정 |

## 8. 방법론으로 일반화되는 것

이 여정에서 반복된 실수는 **모두 같은 형태**였다.

> 한 조건에서 얻은 값을 다른 조건에 그대로 적용했다.

| # | 사례 |
|---|---|
| 1 | 로짓 역압 수정 **이전** 데이터로 `B` 법칙 두 개를 세움 |
| 2 | 세션 드리프트를 `nBatches` 탓으로 귀속 |
| 3 | 콜드 기준값을 분모로 사용 |
| 4 | `att_share` 를 한 `prefix` 에서 재서 전체에 적용 |
| 5 | 예측 `B=16` 을 실측 `B=32` 와 비교 |

그래서 다음 세 가지가 규율로 필요하다.

```text
1. 비교 도구가 조건 일치를 **강제로** 검사한다
     B_actual ≈ S_exec / prefillChunks,  불일치면 비교 실패 처리
2. 측정에 정합성 검사를 내장한다
     stepsum / wall ≈ 1,  단조성,  양수성
3. 시스템을 고친 뒤에는 그 이전 데이터로 세운 법칙을 전부 다시 세운다
```

**사람이 매번 확인하는 방식은 다섯 번 실패했다.**
