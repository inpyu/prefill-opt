## 1. 이 연구가 무엇인가 — 세 문장

1. 라즈베리파이 클러스터에서 LLM 의 **첫 응답 시간(TTFT)** 을 줄이려 한다.
2. TTFT 는 사실상 **KV 캐시를 만드는 시간**이고, 그 계산은 레이어 방향으로 순차라
   노드를 늘려도 잘 안 빨라진다.
3. 그래서 **토큰 축으로 나누고**(블록 병렬), 나아가 **깊이 사슬 자체를 절반으로 줄인다**
   (상위 레이어 KV 를 x_k 에서 직접 사영).

한 문단 버전은 [08-glossary 부록](../08-glossary.md) 에 있다.

## 3. 읽는 순서 — 목적별

### (A-0) "LLM 추론 자체를 잘 모른다" — 먼저 여기

```
04-concepts 1부 → 2부 → 3부   (트랜스포머 → KV 캐시 → 하드웨어)
```

원본 문서를 하나도 안 읽어도 되게 썼다. 여기까지 읽으면 아래 (A)가 술술 읽힌다.
분산(5부)과 선형대수(7부)는 필요해질 때 돌아오면 된다.

### (A-1) "식을 끝까지 따라가고 싶다" — 04 를 읽었거나, 안 읽었어도

```
05-math-attention   (Q/K/V 가 왜 셋인가, RoPE 는 어떻게 유도되나, KV 캐시)
06-math-pipeline    (나눴을 때 시간이 얼마인가 — 11-results 의 모델 유도)
07-math-measurement (perplexity, 오차, 실험 설계 — 13-methodology 의 근거)
```

세 문서 모두 **0부에서 필요한 기반(내적·softmax·분산·로그)을 직접 만들고 시작한다.**
순서 의존이 거의 없으니 궁금한 것부터 봐도 된다.

- "왜 `√d` 로 나누지", "RoPE 가 왜 회전이지" → **05**
- "왜 8노드인데 3.78배지", "입자도가 뭐지" → **06**
- "perplexity 가 왜 486배 튀었지", "왜 번갈아 돌리지" → **07**

### (A-2) "최신 결과만 빨리" — 15분

```

```

막히는 항목이 나오면 [03-glossary-full](03-glossary-full.md) 에서 그 항목만 찾아본다.

## 4. 원본 문서 간 알려진 불일치

읽다가 헷갈릴 지점만 모았다. **원본을 고치지 않고 여기에 기록한다.**

| 항목 | 문서별 값 | 해석 |

| **SDOT 1회의 연산 수** | 04-concepts §4-4: "32 MAC = 64 FLOP" / 11 §5: 피크 **307 GOPS** | **04 가 2배 틀렸다.** 128비트에 int8 은 16개뿐이라 **16 MAC = 32 연산**이다. `4코어 × 2.4 GHz × 32 = 307.2 GOPS` 로 11 과 정확히 맞는다. 64 FLOP 을 쓰면 피크가 614 가 되어 달성률이 68 % → 34 % 로 잘못 나온다. **307 이 정본.** 04 에 정정 블록을 달았고 유도는 [07-math §3-1](07-math-measurement.md#3-1-하드웨어-피크-성능-유도) 에 있다 |
| **`B_min`** | 04-concepts §3-4: 실측 포화점 **32** / 11 §3: `B_min` = **16** | **서로 다른 것을 재고 있다.** 32 는 "더 키워도 이득 없는 포화점", 16 은 "여기까지 줄여도 효율이 유지되는 하한"이다. 스케일링 모델은 16 을 써야 `M=28` 이 나오고 예측이 실측과 맞는다. **인용할 때 어느 정의인지 밝힐 것** ([06-math §4](06-math-pipeline.md#4-m-은-어디서-오나--b_min-의-유래)) |
| **블록 로컬 attention 의 안전성** | 04-concepts §6-1(원본): "짧은 프롬프트에서 더 안전" / 09 §2: **생성이 반복 루프** | **04 의 원래 판단이 반증됐다.** 결정 요인은 블록의 *수* 가 아니라 *크기* 다. Star Attention 은 16~32 K 블록, 여기는 56~112 토큰 — 문맥이 남지 않는다. **09 §2 가 정본.** 04 §6-1 에 정정 블록을 달았다 |
| **동작하는 분산 축** | 07 §1 표: TP2 1.13× / 12 #9: **TP 는 실행된 적 없음** | `--workers` 가 `Auto PP heuristic` 으로 `ppSize = nNodes` 를 덮어써서, **07 의 모든 "TP" 측정치가 사실 PP 다.** 07 §1 표의 축 이름을 그대로 인용하면 안 된다 |
| **단일 노드 prefill** | 07 §1: 37,939 / 06 §2: 32,417 / **11 §1: 30,110** | 회차가 다르다. **최신·정본은 11 의 30,110 ms** 이고, 스케일링 표의 분모가 이 값이다 |

> 07 §1 표와 06 §2 표는 **다른 실험 회차**다. 두 표의 숫자를 섞어 비율을 계산하지 말 것.
> **11-results 의 표는 같은 세션 교차 측정 3라운드 중앙값**이므로 표 안에서는 비교해도 된다.

## 5. 이 폴더를 갱신하는 규칙

1. **새 측정값은 여기 쓰지 않는다.** 원본 00–13 에 쓰고, 여기는 포인터만 갱신한다.
   05~07 은 **원본의 숫자를 유도·검산할 뿐** 새 숫자를 만들지 않는다.
   (검산이 원본과 어긋나면 그것은 **불일치이므로 §4 표에 등재**한다 — 실제로 이렇게 두 건을 찾았다.)
2. 원본에 새 문서가 생기면 §2 표에 한 줄 추가한다.
2-b. **04 의 서술이 이후 실측으로 뒤집히면 지우지 말고 정정 블록을 단다.**
   무엇이 어떻게 틀렸는지가 그 자체로 내용이고, 옛 판단을 인용한 문서가 남아 있기 때문이다.
   그리고 §4 표에 등재한다.
3. 코드 구조가 바뀌면 [01-code-map](01-code-map.md) 의 줄 번호를 다시 확인한다
   (줄 번호는 쉽게 낡는다 — **함수 이름으로 먼저 찾고 줄 번호는 참고로만** 쓸 것).
