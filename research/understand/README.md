그때의 언어로 쓴다. 처음 읽는 사람에게는 진입점이 없다.

## 1. 이 연구가 무엇인가 — 세 문장

1. 라즈베리파이 클러스터에서 LLM 의 **첫 응답 시간(TTFT)** 을 줄이려 한다.
2. TTFT 는 사실상 **KV 캐시를 만드는 시간**이고, 그 계산은 레이어 방향으로 순차라
   노드를 늘려도 잘 안 빨라진다.
3. 그래서 **토큰 축으로 나누고**(블록 병렬), 나아가 **깊이 사슬 자체를 절반으로 줄인다**
   (상위 레이어 KV 를 x_k 에서 직접 사영).

한 문단 버전은 [08-glossary 부록](../08-glossary.md) 에 있다.

## 3. 읽는 순서 — 목적별

### (A-0) "LLM 추론 자체를 잘 모른다" — 먼저 여기

```
04-concepts 1부 → 2부 → 3부   (트랜스포머 → KV 캐시 → 하드웨어)
```

원본 문서를 하나도 안 읽어도 되게 썼다. 여기까지 읽으면 아래 (A)가 술술 읽힌다.
분산(5부)과 선형대수(7부)는 필요해질 때 돌아오면 된다.

### (A) "이 연구가 뭔지 알고 싶다" — 약 1시간

```
08-glossary 부록(한 문단)  →  08 Part 1~3  →  07 §1  →  00 §0~§1
```

08 의 Part 1–3(추론 두 단계 / 연산 / 분산)이 나머지 전부의 어휘를 깔아 준다.
07 §1 은 **실제로 잰 숫자**라 가장 설득력 있는 진입점이다.
막히는 항목이 나오면 [03-glossary-full](03-glossary-full.md) 에서 그 항목만 찾아본다.

### (B) "코드를 만지려 한다" — 약 하루

```
05 Part A (KV 캐시 생성)  →  [01-code-map](01-code-map.md)  →  02, 03, 06
→  06 §6 운영 교훈(반드시)  →  prefill_bench/run_one.sh
```

06 §6 을 건너뛰면 OOM 3종과 디스크 소진을 그대로 다시 겪는다.

### (C) "08 §4 수학을 이해하려 한다" — 08 에서 가장 어려운 부분

```
05 A-2 (왜 순차인가)  →  02-glossary-extra 기호표  →  03-glossary-full Part 4
→  prefill_bench/fit_kv_projection.py
```

03 Part 4 는 08 §4 를 같은 순서로 풀어 쓰되 코드 위치와 수식의 대응을 붙여 두었다.

`fit_kv_projection.py` 는 08 §4 를 **그대로 코드로 옮긴 것**이다.
수식이 안 잡히면 이 스크립트의 `ls_fit`, `rel_err` 를 먼저 보는 게 빠르다.

### (D) "논문을 쓰려 한다"

```
00 §3 (기여 구조)  →  refs.md  →  04-reading-path Stage 0~5
```

## 4. 원본 문서 간 알려진 불일치

읽다가 헷갈릴 지점만 모았다. **원본을 고치지 않고 여기에 기록한다.**

| 항목 | 문서별 값 | 해석 |
|---|---|---|
| 단일 노드 prefill (S=447) | 07 §1: 37,939 ms / 07 §1(d): 36,740 ms / 08: "36.7초", "37.9초" 혼용 | 측정 회차가 다르다. 07 §1 표는 분산 비교용 회차, §1(d) 는 토큰 길이 스윕 회차 |
| lm_head 제한 후 | 06 §2: 32,417 ms | 07 §1 표(37,939)는 **lm_head 제한 이전** 회차로 보인다 — 표끼리 직접 빼지 말 것 |
| 배리어 1회 비용 | 07 §4: 16.3 ms / `nn-network.cpp:99` 주석: 43.9 ms | 43.9 ms 는 **poll 수정 전**, 16.3 ms 는 수정 후. 둘 다 맞다 |
| **발견 #5 의 문서** | 07 이 `06 §7` 로 링크하지만, 06 §7 은 **다른 버그**(트래픽 요약 무한 출력)다 | 발견 #5(배리어 1 ms sleep)를 서술한 문서는 **없다**. 유일한 근거는 `nn-network.cpp:95~105` 주석 — 배리어 43.9 ms 중 회선은 6.9 ms 뿐이고 37 ms 가 sleep 이었다는 분해가 거기 있다. **06 에 §8 로 승격 필요** |
| 노드당 GFLOPS | 00 §1 본문: 30 → 정정 110 | 30 은 dotprod 버그 값. **110 이 정본** ([02](../02-baseline-dotprod-fix.md)) |
| 가중치 크기 | 08: 6.3 GB / 07 §5: 6.32 GB | 같은 값 |
| **attention 비중** | 03 §1 표: S=1789 에서 **57 %** / 03 §7·05 B-1: **13.3 %** | 57 % 는 **깨진 커널이 만든 인공물**이다. 03 §7 이 "H2 재정정"으로 스스로 뒤집는다. **13.3 % 가 정본** — 03 §1 표만 보고 인용하면 틀린다 |

> 07 §1 표와 06 §2 표는 **다른 실험 회차**다. 두 표의 숫자를 섞어 비율을 계산하지 말 것.

## 5. 이 폴더를 갱신하는 규칙

1. **새 측정값은 여기 쓰지 않는다.** 원본 00–08 에 쓰고, 여기는 포인터만 갱신한다.
2. 원본에 새 문서가 생기면 §2 표에 한 줄 추가한다.
3. 코드 구조가 바뀌면 [01-code-map](01-code-map.md) 의 줄 번호를 다시 확인한다
   (줄 번호는 쉽게 낡는다 — **함수 이름으로 먼저 찾고 줄 번호는 참고로만** 쓸 것).
