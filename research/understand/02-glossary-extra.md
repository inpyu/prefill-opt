# 2. 이름 충돌 — 읽기 전에 반드시

**이 세 가지를 모르면 문서가 서로 모순되는 것처럼 보인다.**

## 충돌 1. `A` 가 두 개다

| 표기 | 뜻 | 문서 |
|---|---|---|
| `A` | anchor 블록의 **토큰 수** | 07 §3, §4 |
| `A_l` | 레이어 l 의 **사영 행렬** | 08 §4-3 |

관련 없는 개념이다. 07 과 08 §4 는 **다른 아이디어**다 (§3 참조).

## 충돌 2. "SP" 가 두 개다

| 표기 | 뜻 |
|---|---|
| SP (문헌) | Sequence Parallel — **토큰을 나눠 연산도 나눔** |
| `--sp-size` (dllama) | KV **저장**만 시퀀스 방향으로 쪼갬. 연산은 전 노드 중복 |

[07 §1(c)](../07-design-block-parallel.md) 가 이걸 실측으로 확인한다 —
SP2/SP4 의 gemm 이 단일 노드와 같다(36.5 / 32.8 vs 33.1초).
**dllama 의 SP 는 병렬화가 아니라 메모리 최적화다.**
코드 근거: [`sliceKvCache`](01-code-map.md#2-kv-캐시--08-part-1--05-part-a).

## 충돌 3. "phase" 가 두 개다

| 표기 | 뜻 |
|---|---|
| phase (코드) | prefill 인가 decode 인가 (`controlPacket.phase`) |
| phase diagram (논문) | 대역폭×프롬프트길이×노드수 축에서 **최적 구성이 바뀌는 경계 지도** (00 §3) |

## 충돌 4. 우리 연구에 아이디어가 **두 개** 있다

08 을 처음 읽으면 하나로 보이지만 서로 독립이다.

| | 축 | 문서 | 상태 |
|---|---|---|---|
| **아이디어 1** 블록 병렬 | **토큰** 을 나눈다 | [07](../07-design-block-parallel.md) | 설계 완료, 미구현 |
| **아이디어 2** 깊이 분해 | **레이어** 사슬을 줄인다 | [08 Part 4](../08-glossary.md) | fit 스크립트만 |

둘은 **곱해진다** — 토큰을 N 등분하고, 각 노드 안에서 깊이도 절반으로.
08 부록의 "①②" 가 정확히 이 둘이다.

# 3. 알고리즘 용어

## anchor (앵커)

블록 병렬에서 **모든 노드가 공통으로 보는 앞부분 토큰 구간**.

블록을 독립 인코딩하면 블록 간 attention 이 사라져 정확도가 떨어진다.
프롬프트 맨 앞 A 토큰을 모든 블록의 접두로 붙여 그 손실을 완화한다.
[Star Attention](https://arxiv.org/pdf/2411.17116) 의 핵심 장치.

**우리 쟁점**: Star 는 anchor 를 각 노드가 **재계산**한다. 우리는 **브로드캐스트**한다
([07 §4](../07-design-block-parallel.md)). 재계산은 노드당 연산 2배, 브로드캐스트는
전송 32 MB + 배리어 32회 ≈ 1.1초. **약 12배 차이** — 이것이 07 의 고유 기여 주장이다.

## anchor amortization

Star Attention 의 숨은 전제. 호스트 하나가 **블록을 여러 개** 맡으면 anchor 를
한 번 계산해 여러 블록에 재사용할 수 있어 오버헤드가 희석된다.

**S=128K 라서 성립한다.** 우리 체제(S≤4K, 노드당 블록 1개)에서는 희석할 대상이 없어
anchor 비용이 그대로 2× 로 남는다 → 가설 **H4** ([00 §2](../00-RESEARCH-PLAN.md)).

> [refs.md 인용 주의 §1](../refs.md) 이 중요하다: "GPU 는 재계산이 싸고 SBC 는 통신이 싸다"는
> 단순 반전은 **성립하지 않는다**. 살아남는 논거는 amortization 쪽뿐이다.

## LSE (log-sum-exp) merge / 분산 softmax

각 노드가 **자기 KV 구간에 대해서만** attention 을 계산한 뒤, 부분 결과를
수학적으로 정확하게 합치는 방법.

```
노드 i : partial output O_i,  그리고 그 구간의 log-sum-exp  L_i
병합   : softmax 의 분모를 L_i 들로 재정규화 → 전체 attention 과 동일
```

교환량은 레이어당 헤드당 `(head_dim + 1)` float 뿐이라 사실상 공짜다.
**근사가 아니라 exact 다.** [07 §2](../07-design-block-parallel.md) 가 "KV 를 통합할 필요가
없다"고 말하는 근거이자, Phase C 의 핵심.

## online softmax

softmax 를 **한 번의 순회로** 계산하는 기법. 최대값과 누적합을 함께 갱신한다.
FlashAttention 의 두 축(타일링 + online softmax) 중 하나.

우리 맥락: 06 §5 의 "online softmax 융합" 은 `att` 중간 버퍼(청크당 8.4 MB)를
**실체화하지 않겠다**는 것. attention 2~3× 기대.
LSE merge 와 수학적으로 같은 도구다 — 하나는 노드 간, 하나는 노드 안.

## SwiGLU

Llama 계열의 FFN. `w2( silu(w1·x) ⊙ w3·x )` — 행렬이 **3개**라 FFN 이 무겁다.
레이어 연산의 80.7 % ([00 §1](../00-RESEARCH-PLAN.md)).
코드: `llm.cpp:502/508/514` (`block_matmul_w1`, `w3`, `block_act`).

## residual stream

레이어를 관통하며 계속 더해지는 활성화 벡터 `x_l`. 08 §4-1 의 `x_{l+1} = x_l + ...`
**08 §4 전체가 "x_k 하나만 있으면 위쪽 KV 를 만들 수 있는가" 라는 질문이다.**

## 캘리브레이션 덤프 (calibration dump)

`A_l` 을 적합하려면 실제 `x_k` 와 `K_l` 쌍이 필요하다. 추론을 한 번 돌리며
그 값을 파일로 뽑는 것.

**학습 데이터가 아니다** — 연립방정식의 계수를 모으는 것이다 (08 §4-3).
`DLLAMA_CALIB_DIR` 환경변수, `block_matmul_k/v` **직후·RoPE 이전**에 덤프.
→ [코드 맵 §7](01-code-map.md#7-깊이-분해--08-part-4--07-4)

# 4. 시스템·측정 용어

## straggler (스트래글러)

집합 통신에서 **가장 느린 노드**. 배리어는 전원을 여기 맞추므로, 노드 하나가
느리면 전체가 그만큼 느려진다.

우리 계측에서 `syncWait` 가 곧 straggler 비용이다 (바이트가 안 움직인 대기).
**H1 이 판정하려는 것**: 통신 시간 중 대기가 전송보다 큰가 → TP2 에서 **7:1** 로 그렇다.

> 06 §5 경고: 워커에 구버전 바이너리가 남으면 워커가 6.9× 느려 **전부 straggler** 가 되고
> `wait_frac` 이 오염된다. 다중 노드 측정 전 `md5sum` 대조 필수.

## wave / drainPrefillLogits

`--wave-pipeline 1`. 청크를 파이프라인에 **비동기로** 흘려보내 PP 버블을 줄인다.
청크를 던지고 기다리지 않으므로, 마지막에 밀린 로짓을 한꺼번에 걷어내야 한다 —
그게 `drainPrefillLogits` (`app.cpp:1035`).

**부작용**: wave 는 로짓을 실제로 읽는 유일한 경로라, lm_head 스킵 최적화(06 §4)의
예외가 된다. 또 `forward()` 가 비동기라 op 프로파일링 집계에서 제외된다
(`dllama.cpp:477`).

## back-pressure / poll 대기

수신 측이 아직 읽지 않아 송신이 막히는 상태. `writeMany` 는 이 시간을 `xfer` 가 아니라
**`wait` 로 분류한다** (`nn-network.cpp:877`).

> **발견 #5** 가 여기다: 대기 루프에 1 ms sleep 이 있어 배리어 1회가 43.9 ms 였다.
> 수정 후 16.3 ms. TP2 가 42 % 빨라졌지만 PP4 는 3 % 뿐 — 07 §1(b) 의 "구조적 대기" 근거.

## turbo mode

`NnNetwork::setTurbo` (`nn-network.cpp:773`). 소켓 옵션(주로 `TCP_NODELAY` 계열) 전환.

## P/D disaggregation

prefill 과 decode 를 **아예 다른 기계에** 배치하는 서빙 구조 (DistServe, Splitwise).
"두 단계는 다른 기계다"를 시스템으로 밀어붙인 사례. 04 Stage 1.

## continuous batching

요청 단위가 아니라 **iteration 단위**로 스케줄링 (Orca). 오늘날 서빙 엔진의 기본.
04 Stage 1.

## roofline

산술 강도(x축) vs 달성 성능(y축) 그래프. 대각선(대역폭 한계)과 수평선(연산 한계)이
만나는 지점이 **machine balance**. 08 Part 2 의 "균형점"이 이것이다.

00 §3 의 phase diagram 은 **roofline 을 분산 축으로 확장한 것**이라고
04 Stage 0 이 명시한다.

# 5. 평가·논문 용어

## matched-accuracy 비교

근사 기법과 exact 기법을 비교할 때, **정확도를 같은 지점에 맞춰 놓고** 속도를 재는 것.

우리가 근사(블록 병렬)를 쓰므로, exact Ring CP 를 직접 구현해 같은 정확도에서
비교해야 한다 (00 §3 Baseline, 07 §6). **"근사인데 exact 와 비교 불가"** 라는
리뷰어 공격에 대한 대비다.

## RULER / LongBench / needle-in-haystack

장문 컨텍스트 정확도 벤치마크. 07 §6 의 정확도 검증에 쓴다.
Star Attention 은 4~8블록에서 97~100 % 를 보고한다.

> **우리에게 유리한 조건**: 우리는 블록이 4~8개로 적다. 초장문을 겨냥한 기존 연구는
> 수십 블록을 쓰므로 블록 간 attention 손실이 훨씬 크다 (07 §6).

## measurement study

새 기법이 아니라 **"기존 설계의 전제가 이 환경에서 깨진다"는 측정 자체**가 기여인 논문.
00 §3 의 기여 1번이 이 형태다. 예시는 04 Stage 5.

## baseline 위생 (baseline hygiene)

우리 구현의 버그를 고치는 것은 **기여가 아니다**. 발견 #1~#4 가 전부 여기 해당한다.
"SBC 라서 느린 것"과 "distributed-llama 라서 느린 것"을 분리하지 않으면
논문 주장 전체가 무너진다 → 03 §4, 06 도입부.

llama.cpp 를 외부 기준선으로 두는 이유가 이것이다 (현재 **85 %** 도달).
