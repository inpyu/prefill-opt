# 06. 기각한 아이디어들 — 그리고 왜 기각했는가

**이 프로젝트에서 분량이 가장 큰 부분이다.** 단순한 negative 나열이 아니라,
각각 *왜 볼 필요가 없는지*를 근거와 함께 남긴다. 나중에 같은 길로 다시 들어가지
않기 위해서다.

---

## 6.1 att/ff 서브블록 분할 (partition 축)

**아이디어.** 32 레이어를 64 서브블록(att | ff)으로 쪼개면 분할 입자도가 두 배가
되어 스테이지 균형이 좋아질 것이다.

**기각 근거.** `S=1789` 와 `S=7212` **양쪽에서 비활성**이다.

```
J4-R (S=7212, 깨끗한 재측정):   0.986 / 1.000
```

한때 `S=7212` 에서 활성으로 보였고 `δ_p = 61%` 라는 값도 나왔는데, **둘 다 오염된
데이터였다.** 재측정하니 예측이 아니라 **측정이 흔들린 것**이었다.

**교훈.** "긴 프롬프트에서는 분할축이 살아난다" 는 직관이 틀렸다.
교차점 양쪽 모두에서 죽어 있다.

---

## 6.2 CoRePP / CP island

**기각 근거 — balanced-capacity contraction lemma.**

스테이지 내부 병렬화로 얻을 수 있는 이득에는 구조적 상한이 있다.

```
intra-stage 병렬 이득  ≤  1/(M + N − 2)
```

`M`(마이크로배치 수)과 `N`(스테이지 수)이 커질수록 상한이 급격히 작아진다.
파이프라인이 이미 잘 채워져 있으면 스테이지 안을 더 쪼개도 얻을 게 없다.

**이것이 이 프로젝트에서 가장 쓸모 있는 기각 도구다.** 여러 축을 한 번에 닫는다.

---

## 6.3 WCEP (Weight-Compiled Prefill)

**아이디어.** 가중치를 미리 분석해 심볼릭하게 연산을 줄인다.

**기각.** 사전 등록한 게이트로 **6~10주짜리 계획을 약 1일 만에 닫았다.**

필요 커널 속도향상을 먼저 계산한 것이 결정적이었다.

```
세 길이 기하평균 E2E 1.20× 를 얻으려면  →  r ≥ 1.334
```

WCEP 가 도달 가능한 값이 여기 한참 못 미쳤다.

**부산물이 더 값졌다.** Phase 1a 를 **세 번 무효화**했다.

| 무효화 사유 | 내용 |
|---|---|
| 회계 단위 불일치 | baseline 을 128 MAC 으로 봤는데 실제는 separate mult/add 라 256 |
| 파일 포맷 오인 | embedding 을 Q4_0 로 가정했으나 실제 F32 (1.68 GiB 오프셋) |
| 순서 오인 | FFN 을 Gate→Up→Down 으로 봤으나 실제 Gate→Down→Up |

세 번째는 특히 위험했다 — **원소 개수가 같아서 byte offset 검사를 통과했다.**

> **교훈: 검증기를 먼저 쓴다.** 이걸 미룬 것이 이 프로젝트에서 가장 비쌌다.

---

## 6.4 QCFuse (중간 버퍼 제거)

**아이디어.** quantize/cast 중간 버퍼를 없애 메모리 트래픽을 줄인다.

**기각 근거 — 상한이 너무 낮다.**

```
386.3 + 224.1 + 193.0 + 37.8 = 841.2 ms = 전체의 2.45%
```

**모든 중간 버퍼를 완전히 없애도 2.45% 가 상한**이다. 구현 난이도 대비 얻을 게 없다.

---

## 6.5 KP-SDOT (K-panelization)

**아이디어.** Down projection 의 `K=14336` 이 길어서 캐시를 넘치니 K 를 패널로 쪼갠다.

**기각 근거 — 교락 변수였다.**

dup/shared 대조를 하니 shared 경로는 **panel 68~238 KiB 에서 327~334 GOPS 로
평탄**했다. `K` 길이가 원인이 아니라 **스레드별 중복 packing** 이 원인이었다.
KP-SDOT 은 없는 문제를 푸는 것이었다.

**부산물은 보존한다.** accumulator 저장·복원으로 K-panel continuation 이
bit-identical 함을 확인했다(P=64/128/224 모두 통과). 나중에 필요하면 쓸 수 있다.

**교훈.** 스윕 하나로 원인을 단정하지 않는다. K-sweep 은 *중복 pack 조건에서만*
측정됐기 때문에 K 가 원인처럼 보였다.

---

## 6.6 `B ∝ S` / `B ∝ √S`

**기각 근거 — 단조가 아니다.**

```
최적 B:   S=512 → 16,   S=2048 → 32,   S=7212 → 16
```

어떤 단조 함수로도 맞출 수 없다. 캘리브레이션 격자에서 고른다.

---

## 6.7 Operator/topology-aware placement `π`

**철회.** 근거였던 순위 역전이 재현되지 않았다.

```
Kendall τ:   −0.29  →  +0.111
```

**현재 기여로 제시할 근거가 없다.** 스칼라 모델로 노드 이종성을 다루려던 시도도
같이 철회했다.

**구조적 이유.** 8 GB / 16 GB 군이 **같은 CPU** 라 노드 성능 이종성이 애초에 작다.
차이는 RAM 용량이고 그건 계산 속도가 아니다.

## 6.10 기각에서 배운 메타 교훈

| 교훈 | 출처 |
|---|---|
| **검증기를 먼저 쓴다** | WCEP 3회 무효화 |
| **상한을 먼저 계산한다** | QCFuse 2.45%, WCEP r≥1.334 |
| **스윕 하나로 원인을 단정하지 않는다** | KP-SDOT 교락 |
| **직관이 아니라 A/B 로 축을 닫는다** | partition 축 |
| **재현되지 않으면 철회한다** | placement `π` |
| **구조적 상한이 있으면 그것부터 본다** | contraction lemma |
