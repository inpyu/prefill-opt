# 07. 측정 방법론과 검증 계층 — 스스로를 속이지 않기 위한 장치

이 프로젝트에서 **틀린 결론을 낸 횟수가 맞은 결론보다 많다.** 그래서 측정 장치
자체가 기여의 일부다.

---

## 7.1 앵커 설계 — 왜 필요했나

`S=1789` 의 `B` 축 이득이 한때 **1.013×** 로 보였다. 나중에 같은 축을 다시 재니
**1.140×** 였다. 차이의 원인은 축이 아니라 **세션 간 비교**였다.

그래서 규칙을 만들었다.

```
1  웜업 1회를 버린다
2  순서를 A,A,B,B,A,A,B,B,A 로 교차해 세션 드리프트를 상쇄한다
3  매 실행 전 워커를 전부 재기동한다
4  쌍 비율 = (시간상 앞 A · 뒤 A 의 기하평균) / B
5  그 쌍 비율들의 기하평균을 R 로 보고한다
6  flock 으로 벤치 간 배타 실행
```

**같은 세션 안에서만 비율을 만든다. 세션 간 절대값은 비교하지 않는다.**

### 효과

| 통제 여부 | 변동 |
|---|---|
| 통제 없음(워커 재기동 없음, 세션 혼재) | 한때 "최대 51%" 로 관측 |
| **통제 후** | BASE 3.0~3.5%, SP 2.1~4.0%, 쌍 비율 log-SD **±1.4%** |

> "변동이 커서 잴 수 없다" 는 결론은 **틀렸다.** 통제하면 1.05× 차이도 분리된다.
> 이 정정은 `research/20` 에 반영했다.

## 7.2 검증 계층 — 출력 해시는 검증기가 아니다

SharedPack 구현 도중 축 규약을 두 곳에서 반대로 읽었다.

```
kBlocks 가 128/448 이 아니라 1
Down packed 버퍼가 필요량의 1/3.5
```

**이 상태에서 E2E 로짓 해시가 BASE 와 비트 단위로 일치해 통과했다.**
(왜 통과했는지는 규명하지 못했고, 수정 후에는 무의미해졌다.)

그래서 정확성을 **계층**으로 나눈다.

```
1  packed bytes 동일        ← 커널이 실제로 소비하는 중간 표현
2  GEMM output 동일
3  stage output 동일
4  final logits 동일        ← 마지막 회귀 검증으로만 유용
```

**4번은 1~2번을 대체하지 못한다.**

### `DLLAMA_VERIFY_PACK`

matmul 이 공유 버퍼와 **자기가 다시 계산한 pack** 을 대조한다.
종료 시 **항상** 요약을 출력한다.

```
[VERIFY_PACK_SUMMARY]
comparisons=2688
bytes_checked=530317312
mismatches=0
```

mismatch 있을 때만 찍으면 *"검증했고 0건"* 과 *"환경변수가 빠져 검증 자체를 안 함"* 을
구분할 수 없다. 워커는 SIGTERM 으로 죽으므로 **시그널 핸들러에서도** 찍는다
(첫 시도에서 워커가 전부 0으로 나와 이 문제가 드러났다).

### 항상 켜진 assertion

검증기는 개발용 안전망이다. shape 오류는 **정상 실행에서도** 즉시 막아야 한다.

```
pack 입력 폭 == 이 matmul 의 K
버퍼 용량 >= rowGroups × kBlocks × sizeof(block_q8_0x4)
```

실제로 이 두 조건이 각각 오독 두 건을 통과시켰다.

### 타입으로 막기

packed 버퍼를 `F_32` 바이트 컨테이너로 쓰던 것이 크기 오류를 숨겼다.
`size2D(F_Q80, nBatches, K)` 로 바꾸니 **폭이 곧 K** 가 되어 산술 실수 여지가 사라졌다.
(`block_q8_0x4` 는 `NnBlockQ80` 의 재배열이라 바이트 수가 정확히 같다.)

## 7.3 artifact 규칙

```
artifacts/<run-id>/
  results_*.tsv      결과 (헤더에 설계·구성·해석 주의사항)
  raw/*.log          원본 로그
  checksums.txt      .bin 은 ignore 하되 해시는 커밋
  invalid/           무효 세션을 지우지 않고 사유와 함께 보존
```

**무효 결과를 지우지 않는다.** 대신 `invalid/` 로 옮기고 헤더에
사유·수정 커밋·유효본 경로를 박는다. 실제로 축 규약 오독 빌드의 결과가
최종 결과처럼 남아 있어 리뷰어가 오독할 뻔했다.

`checksums.txt` 에는 **오독 빌드가 낸 해시 9종을 명시**해 둔다.

## 7.4 반복해서 밟은 함정

| 함정 | 횟수 | 대응 |
|---|---|---|
| `pgrep -f`/`pkill -f` 가 자기 명령줄 매칭 | **7** | `-x` 사용. 정리와 실행을 다른 명령으로 분리 |
| `\| head` 가 SIGPIPE 로 실행 중단 | 2 | 긴 실행은 파일로 받고 나중에 grep |
| 소표본 관측을 일반 결론으로 확대 | 3 | 앵커 설계 + 사전등록 기준 |
| 회계 단위 불일치 | 3 | baseline 과 최적화가 같은 단위인지 매번 확인 |
| 파일 포맷 오인 | 2 | 검증기를 먼저 쓴다. byte 크기만으로 부족 |
| 실험 중 재빌드 | 1 | flock 은 벤치 간 배타만 보장한다. 빌드는 안 막는다 |
| 워커 실행 중 `scp` → `ETXTBSY` | 1 | 배포 전 `pkill -x dllama`, 배포 후 전 노드 md5 대조 |
| `--steps` 를 프롬프트 토큰 수 이하로 | 1 | 프리필 로짓만 필요해도 `steps > nPromptTokens` |
| 축 규약을 확인 없이 가정 | 1 | 선언을 읽는다: `size2D(t, y, x)` |
| E2E 해시를 커널 정확성 증거로 사용 | 1 | 중간 표현 대조 계측을 먼저 만든다 |

**가장 값비쌌던 것: 검증기를 나중으로 미룬 것.** Phase 1a 를 세 번 무효화했다.

## 7.5 개발 진행 방식을 바꾼 교훈

측정 장치와 같은 이유로 남긴다. 이 규칙들이 **현재 설계를 유지하게 만든** 판단
기준이다.

| 교훈 | 어디서 배웠나 |
|---|---|
| **검증기를 먼저 쓴다** | 검증을 미뤄 한 단계를 세 번 무효화했다 |
| **상한을 먼저 계산한다** | 구현 전에 도달 가능한 최대치를 재니 며칠 만에 방향이 갈렸다 |
| **스윕 하나로 원인을 단정하지 않는다** | `K` 가 원인처럼 보였으나 교락 변수였다. dup/shared 대조로 갈렸고, 그것이 SharedPack 으로 이어졌다 |
| **직관이 아니라 A/B 로 축을 닫는다** | "긴 프롬프트에서는 분할축이 살아난다" 는 직관이 틀렸다 |
| **재현되지 않으면 철회한다** | 노드 이종성 근거가 재현되지 않아 그 설계를 내렸다 |
| **구조적 상한이 있으면 그것부터 본다** | `1/(M+N−2)` 하나가 여러 대안을 함께 닫았다 |

**가장 값비쌌던 것: 검증기를 나중으로 미룬 것.**
